# 拼好家工作台 · UI 设计系统性评审报告

> 评审时间：2026-09-28 · 评审人：像素君（UI Designer）
> 评审对象：NAS 正式部署 `192.168.124.77:4174`（最新代码，含锅宝新引擎）
> 评审方法：**设计规范（设计规范-v2.0.md / brand-spec.md）× 实现代码（app.css 5295 行）× 真机截图目检**（6 模块 × 桌面 1440 / 移动 390，共 12 张全页截图，见 `shots/`）
> 评审维度：视觉一致性 / 布局与信息层级 / 交互流程 / 可用性 / 可访问性

---

## 0 · 总评：底座优秀，打磨不足

**设计系统的"骨架"是健康的**：令牌纪律近乎满分（513 处 `var(--*)` 引用，`:root` 外仅 2 处裸 hex 且都在令牌块内）；9 色账号×平台语义在账号矩阵、内容计划落地良好；无障碍基线（`focus-visible`、`prefers-reduced-motion`）存在；空态大多有引导文案。

**问题集中在"最后一公里"**：强调色预算失控、空值表达混乱、规范与实现脱节（主题 5→2）、移动端看板溢出无提示。全是不伤筋骨但持续放血的问题——每个单独看都不大，合起来让产品显得"没做完"。

| 维度 | 评级 | 一句话 |
|---|---|---|
| 视觉一致性 | 🟡 中 | 令牌纪律好，但 accent 使用规则被普遍违反 |
| 布局与信息层级 | 🟡 中 | 主指标高亮模式不统一，技术信息占据指标位 |
| 交互流程 | 🟢 良 | toast/撤销/选中态约定在位，移动端拖拽是硬伤 |
| 可用性 | 🔴 差 | 空态词汇 6 种说法、0 值高亮、整页空表头 |
| 可访问性 | 🟡 中 | 基线在，但图标字符化、溢出无感知拉低分数 |

## 1 · 视觉一致性

### V1 🔴 强调色预算失控（规范 §1.2 明确「每屏 ≤2 处主强调」）

**现状**：今日工作台首屏同时出现——蓝色主指标卡（82,200）+ 日历「今天」整块蓝底 + 选题流水线 5 条进度条全蓝 + 「待补表现 1 条」蓝字。一屏至少 4 处主强调。
**影响**：用户视线没有落点，真正的主 CTA 被淹没；规范里最核心的一条色彩纪律名存实亡。
**方案**：① 进度条回归规范默认（`--fg-2` 灰，仅当前选中行用蓝）；② 日历「今天」改为 accent 描边 + 细辉光（规范 §3.6 本来就是这么写的：`.today` = accent 描边 + focus-ring 辉光，实现成了实心填充）；③ 每页只保留 1 个蓝色主指标卡。

### V2 🔴 蓝色主指标卡的位置和逻辑全站不统一

**现状**：今日工作台蓝卡在第 1 张（总播放）、灵感雷达在第 2 张（收录作品）、数据复盘在第 2 张（播放/阅读）、账号矩阵在第 1 张（账号覆盖）、知识资产**没有**蓝卡。用户无法形成"蓝卡=什么"的预期。
**影响**：跨页导航时每页的视觉锚点位置都在变，认知负担加重；而且数据复盘页用蓝卡高亮一个 **0 值**，强调色在强调"什么都没有"。
**方案**：定死规则——蓝卡恒为第 1 张，恒为该模块"北极星指标"；**0 值/无数据时禁用蓝卡样式**（退化为普通卡 + 空态灰字）。

### V3 🟡 导航图标用字符符号，非规范要求的内联 SVG

**现状**：侧栏 6 个导航图标是 `⌂ ⌁ ▦ ↗ ◎ ◇` 字符（规范 §7：图标用内联 SVG，stroke 1.5–2）。截图中图标发虚、粗细不一，高 DPI 下边缘模糊。
**影响**：视觉精度掉档，与"pixel-perfect"目标相悖；字符图标在不同平台字体下渲染不可控。
**方案**：换 6 个 16×16 内联 SVG（stroke 1.5，`currentColor`），半小时工作量。

### V4 🟢 令牌纪律近乎满分（值得保持）

513 处 `var(--*)`、`:root` 外零裸 hex、9 色语义在账号卡/看板顶条正确落地。**这是全站做得最好的一层，后续改动能不动就不动。**

## 2 · 布局与信息层级

### L1 🟡 技术指标占据主指标卡位

**现状**：账号矩阵页三张大指标卡之一是「当前数据源 **SQLite**」，用 display 大字号展示。
**影响**：「SQLite」是实现细节不是业务指标，用户（运营视角）看到无法行动；占用了一个本可放「粉丝总量」等业务指标的黄金位置。
**方案**：数据源信息降级到侧栏脚注（那里已有「SQLite 已连接」状态点，重复了）；指标卡换业务指标或干脆收为 2 张。

### L2 🟡 指标卡用 display 大字显示「待接入」

**现状**：今日工作台第 4 张卡「粉丝快照」的值是「待接入」三个大字，与其它卡的 `82,200` / `6,070` 同一字号层级。
**影响**：文字冒充数字，破坏指标卡的扫描节奏（用户扫大数字时读到的是一句状态说明）。
**方案**：未接入状态用 `.meta` 小字 + 灰化卡片 + 「去配置 →」链接，大数字位留 `—`。

### L3 🟡 主 CTA 给了次要操作

**现状**：灵感雷达页唯一的白底主按钮是「导出」，而核心动作「刷新雷达」是次级灰按钮。
**影响**：每页一个主 CTA 的名额给了低频操作，高频动作视觉上被降级。
**方案**：互换按钮层级（刷新雷达 = primary；导出 = secondary）。

### L4 🟡 eyebrow 编号重复

**现状**：账号矩阵 `ACCOUNT MATRIX / 05`，知识资产 `METHOD LIBRARY / 05`——编号撞车（知识资产应为 06）。
**影响**：小问题，但 eyebrow 是"全站地图"性质的编号系统，错了就失去了存在意义。
**方案**：改知识资产为 `/ 06`，并把编号规则写进规范（按导航顺序 01–06）。

### L5 🟢 看板/日历/指标卡的栅格与等高行符合规范

内容计划五列看板、账号矩阵三卡网格、dashboard 的等高行模式都正确落地，桌面端布局不需要动。

## 3 · 交互流程

### I1 🔴 移动端看板横向溢出，且无任何可滚动提示

**现状**：内容计划五列看板在 390px 下只显示 1.5 列，「脚本库」列被硬切一半；无滚动条、无边缘渐隐、无滑动提示。
**影响**：移动端用户根本不知道右边还有 3.5 列——五状态流水线直接退化成两状态。这是**功能级**缺陷，不是视觉瑕疵。
**方案**：① 看板容器加滚动吸附（`scroll-snap-type: x mandatory`）+ 右边缘 24px 渐隐遮罩；② 列头下方加「1/5」位置指示点；③ 或移动端降级为「状态筛选 + 单列列表」模式（改动大，但触屏体验最正）。

### I2 🔴 看板拖拽在触屏上不可用，无替代路径

**现状**：「拖动卡片可推送状态」是看板的核心交互；触屏设备没有拖拽。
**影响**：移动端无法推进卡片状态，流程断链。
**方案**：卡片上加「推进 →」按钮（或长按菜单），与拖拽并存；提示文案按设备切换（触屏显示「点卡片右侧箭头推进状态」）。

### I3 🟡 主题系统从 5 套缩水到 2 套，规范未更新

**现状**：规范 §4 定义 5 套主题（framer/glass/fluent/bento/retro），`app.css` 里只有 `data-theme="fluent"` 一套覆盖，侧栏切换器只剩 2 个圆点。
**影响**：规范在描述一个不存在的能力——这正是之前 as-built 发现的「文档失真」同类问题；新页面按规范做主题适配会白做。
**方案**：二选一：补齐 5 套（工作量大），或**把规范改成 2 套**（诚实，推荐）。规范的权威来自"说的都真"，而不是"说的都多"。

### I4 🟢 toast / 撤销 / 加载态 / 选中态的交互约定执行良好

规范 §5 的约定（toast 反馈、可撤销、`.on` 选中态可区分）在各页均有体现，交互骨架不需要动。

## 4 · 可用性

### U1 🔴 空值表达全站 6 种说法，无统一词表

**现状**：`0`（大数字）/ `—` / `待接入` / `暂无` / `未绑定` / `0%` 混用。同一张灵感雷达表格里「可见数=暂无」「文案=未绑定」；数据复盘里「平均互动率=—」而隔壁是「0」。
**影响**：用户要猜每种说法的差异（0 是"真为零"还是"没数据"？「暂无」和「未绑定」区别在哪？）；扫描表格时认知成本翻倍。
**方案**：建立**空值词表**并写进规范 §7：

| 场景 | 统一表达 |
|---|---|
| 有统计口径、值确实为零 | `0`（普通字重，不用 display 大字） |
| 无统计口径/功能未接入 | `—` + 小字说明 + 配置链接 |
| 列表/表格单元格无值 | `—` |
| 需用户补录 | 「补数据 →」行动链接（现行做法，保留） |

### U2 🟡 空表格渲染完整表头 + 巨大空白

**现状**：数据复盘「数据明细」无数据时，10 列表头完整渲染，下面一大片黑。
**影响**：页面显得"坏了"而不是"空的"；移动端同样问题。
**方案**：无数据时表头替换为空态块（插画位 + 「本周期暂无数据」+「去补录 →」），有数据再渲染表。

### U3 🟡 半张表格的列常年为空

**现状**：灵感雷达数据明细的「可见数」「播放」列全「暂无」，「文案」列全「未绑定」——10 行 × 3 列纯占位。
**影响**：有效信息密度被稀释 30%+；横向滚动（移动端）时用户滑过去看到的还是空列。
**方案**：列级空值治理——某列全空超过 N 天则默认收起（表头加「+ 显示更多列」）；或合并为「数据完整度」单列（如 ●○○ 三点图）。

### U4 🟡 「本周发布进度」日期与当前周不符

**现状**：今日工作台显示「2026-08-28 至 2026-09-04」，但评审当天是 09-28（数据复盘页同周期正确显示 9月28日–10月4日）。
**影响**：dashboard 的"本周"是错的，进度条归零的归因会被误判（用户以为没发布，实际是看错了周）。
**方案**：排查 dashboard 周区间计算逻辑（疑似写死或时区/缓存问题），与数据复盘页共用同一个周期工具函数。

### U5 🟡 dashboard 底部「灵感速递」空 section 无空态

**现状**：标题 + 一句说明后直接接 footer，桌面端和移动端同现。
**影响**：页面收尾突兀，像没加载完。
**方案**：补空态（「暂无灵感信号 · 去灵感雷达看看 →」）或无数据时整段隐藏。

### U6 🟢 低优先级：复盘结论 5 个默认全开的巨大 textarea

单屏 5 个约 200px 高输入框，压迫感强。建议默认折叠为 5 个问题列表，点哪个展开哪个（手风琴），已有内容时自动展开。

## 5 · 可访问性

### A1 🟡 溢出内容对辅助技术不可见

**现状**：移动端看板横向溢出区域无 `aria-label` 说明，也无焦点顺序兜底（tab 不到被切掉的列）。
**影响**：读屏用户在移动端完全感知不到后 3 列存在（与 I1 同源，但维度不同：I1 影响视觉用户，A1 影响读屏用户）。
**方案**：看板容器加 `role="region" aria-label="内容流水线看板，共 5 列，可横向滚动"`；保证每张卡片可 tab 到达（滚动容器内元素自动入焦点序）。

### A2 🟡 字符图标的可访问名称依赖相邻文本

**现状**：导航图标（⌂ 等）无 `aria-hidden`，部分读屏会念出"方形""菱形"等字符名。
**影响**：读屏输出出现无意义噪音（"菱形 知识资产"）。
**方案**：图标元素加 `aria-hidden="true"`（换成 SVG 时一并处理，见 V3）。

### A3 🟢 基线项全部在位

`:focus-visible` 描边、`prefers-reduced-motion` 块、toast 的 `role="status" aria-live="polite"`、日历格 `aria-label`、主题切换 `radiogroup`——规范 §6 的基线全部落地，保持即可。

## 7 · 整体改进方向（三句话）

1. **从"规范写得全"转向"规范说得真"**：本次 17 个问题里约 1/3 是规范与实现脱节（主题、日历今天态、CTA 层级）。建议每次 UI 改动后跑一次「规范 checklist 抽查」（规范 §8.4 已经有现成的，缺的是执行）。
2. **建立两个词表，终结即兴表达**：空值词表（U1）+ 强调色使用规则（V1/V2）。全站 80% 的"显得没做完"感来自这两处的即兴发挥。
3. **移动端从"能看"补到"能用"**：当前移动端是桌面布局的被动压缩，看板这种核心交互需要主动为触屏设计替代路径（I1/I2 修完后，建议把六模块在 390px 下全部走查一遍真实操作，而不只是截图）。
