## 3 · ⚠️ 本次踩到一个真实事故（已修复并固化）

**现象**：批量移动写成 `git mv "$SRC/${FILES[0]}" "$DST/"`。
zsh **数组下标从 1 开始**，`${FILES[0]}` 是**空串** → 整条命令退化成 `git mv "$SRC/" "$DST/"`，
**把整个代码目录搬进了 `docs/specs/`**，而 **退出码 0、无任何报错**；后续 7 条因源目录消失而静默失败。

**修复**：原地 `mv` 搬回，**93 个文件计数核对无损**（`mv` 是纯重命名，零数据损失）。

**另发现两个本机环境事实**

1. **`git mv` 不可用** —— 后台进程反复重建 `.git/index.lock`；
   且沙箱禁止 unlink `.git/`，git 能建锁却删不掉，症状自我强化。
   → 降级为 **`mv` + `git add -A`**。
   ⚠️ 关键认知：**git 的 rename 识别是「内容相似度」在 diff/commit 时算的，不是 `git mv` 赋予的** ——
   普通 `mv` 同样得到 `R`，「必须用 `git mv` 才保历史」是错的。
2. **中文 `grep` 的 `\|` 交替在本机 shell 会静默失败**（返回空、退出码 1，看起来像"没命中"）。

**已固化**：新建技能 `doc-set-relocation`（铁律 2 / 3 即这两条），并写入用户级记忆第十二条。
