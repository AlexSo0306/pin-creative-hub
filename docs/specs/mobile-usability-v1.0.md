# Spec: 移动端可用性修复 v1.0

> 建立时间：2026-09-21
> 状态：**待评审**（Phase 1 · SPECIFY 门禁）
> 依赖：`docs/specs/as-built-2026-09-21.md` §4 第 14–17 条（本次的证据来源）

---

## 1. Objective

让工作台在手机浏览器（375×812 起）上**可用**，而不只是"能打开"。

**当前状态**：CSS 层已做了大量响应式工作（4 档断点、16 个媒体查询、≤640px 有 5 个逐页 block），
但有 **3 处硬缺陷**导致手机上实际不可用。

**目标用户**：Alex 本人，在手机上查看排期、推进内容状态、补数据。

**验收定义**：手机上 6 个模块全部可达，且「内容计划」与「数据复盘」的核心动作可完成。

## 2. 缺陷清单（证据均来自代码）

| # | 缺陷 | 证据 | 严重度 |
|---|---|---|---|
| **D1** | **手机上只剩 2 个导航入口** | `app.css` ≤640px 块：`.main-nav a:nth-child(-n+4) { display: none }` → 隐藏「今日工作台 / 灵感雷达 / 内容计划 / 数据复盘」；全库无 `hamburger` / `bottom-nav` / `mobile-nav` 任何替代机制 | 🔴 P0 |
| **D2** | **内容计划拖拽在触屏不可用** | `content-plan.js` 只有 `draggable` + `dragstart/dragover/dragleave/dragend`，**零 pointer / touch 事件**。HTML5 DnD 在 iOS Safari 不触发 | 🔴 P0 |
| **D3** | **重建丢焦点，软键盘会收起** | `focus()` 全库 6 处、`activeElement` 仅 2 处（均在 `knowledge.js`）、**无 `selectionStart` 保存**。整页 `innerHTML` 重建后输入中断 | 🟡 P1 |

### 关键发现：D1 违反了项目自己的设计规范

`docs/specs/设计规范-v2.0.md` §2.3 原文：

> ≤920px：所有 grid 收为 1 列；`.app-shell` 单列；侧边栏折叠为顶部横条（**导航横向滚动**、CTA 收窄、`.side-foot` 隐藏、主题切换器收为色块圆点行）

规范要求的是**导航横向滚动**，代码却用 `display: none` 把 4 项删了。
→ **D1 不是"缺功能"，是实现偏离了已批准的规范。** 最小修复路径存在。

（附带漂移：规范声明断点为 ≤1100 / ≤920，实际为 1180 / 1120 / 860 / 640。）

## 3. 需求

### 3.1 导航可达性（P0）

- ≤640px 下，**6 个模块全部可到达**（可见并可点击，或经一次明确的展开动作）
- 不引入"隐藏入口"——当前页必须始终可见（否则用户不知道自己在哪）
- 保留 `.on` + `aria-current="page"` 的选中态语义

### 3.2 看板状态推进（P0）

- ≤640px 下，能把内容卡从「选题池」推进到「已发布」（及回退）
- 必须与看板的**横向滚动**共存——两者都是横向手势，存在冲突，见 §6 开放问题
- 桌面端（≥860px）行为不变

### 3.3 输入连续性（P1）

- ≤640px 下编辑内容卡标题时，**连续输入不中断**、软键盘不收起
- 实现方式：重建前保存 `document.activeElement` + `selectionStart/selectionEnd`，重建后恢复

## 6. Open Questions（需你拍板）

1. **导航方案选哪个？**
   - **A · 恢复横向滚动**（规范原文方案）：删掉 `display:none`，给 `.main-nav` 加 `overflow-x:auto` + `white-space:nowrap`。**改动约 5 行**，完全符合已批准的规范。缺点：6 项在 375px 下要轻微横滑，可发现性一般
   - **B · 底部标签栏**：移动端最标准。但 6 项偏多（通常 5 项），且要新增 DOM 与样式
   - **C · 汉堡菜单 + 抽屉**：项目已有 `.drawer` 模式可复用。缺点：多一次点击，且当前页在抽屉里不可见
   - **推荐 A**——最小改动、符合规范、不引入新交互模式。若实测体验差再升级到 B

2. **看板手势冲突怎么解？**（D2 的隐藏难点）
   手机上「横向滚动看 5 个状态列」与「横向拖拽卡片」是同一个手势。三种解法：
   - **长按进入拖拽**（long-press 300ms 后锁定卡片，再拖）—— 保留拖拽手感，需用户学习
   - **改用按钮**：卡片上加「→ 推进到下一状态」按钮 —— 最稳，但失去拖拽的直观性
   - **桌面拖拽 / 手机按钮**：按断点分两套交互 —— 体验最好，代码分叉最多
   - 需要你的偏好，因为它直接决定 D2 的实现方式

3. **D3 要不要现在做？** 它是 P1，不属于"能不能用"，属于"好不好用"。可以推迟。
