> 版本：v2.0

> 前置文档：[产品总览](../../拼好家内容创作中心/README-产品总览.md) | [现状基线](as-built-2026-09-21.md)

## 1. Problem Statement

v1.0 的今日工作台只是一个"对标资料库快照 + 原型占位"——用户在首页看完对标作品数后，仍然不知道今天该干什么。一个多账号、多平台的自媒体运营者每天最核心的需求是：**打开工作台就知道今天要做什么、整体数据怎么样、哪个选题该继续写、哪天发了什么**。这些信息分散在灵感雷达、内容计划和数据复盘之间，首页没有聚合。

**v2.0 要解决的核心问题**：让今日工作台从"资料库快照"升级为"运营指挥中心"——聚合数据总览、内容日历、选题进度、今日待办和表现速览，成为用户每天打开的第一个页面，也是唯一需要看的概览页面。

**不解决的成本**：用户每天需在多个模块间跳转才能拼凑出"全貌"，容易遗漏今天该做的事、忘记补数据、忽视某账号长期不更新。

---

## 2. Goals

| # | 目标 | 衡量方式 |
|---|------|---------|
| G1 | 用户打开首页 10 秒内感知整体运营数据（播放/点赞/粉丝/分享） | 数据总览卡片渲染时间 < 500ms |
| G2 | 用户能在日历上快速定位哪天在哪个账号发布了什么内容 | 从打开首页到定位某日发布内容 < 5 秒 |
| G3 | 用户能从首页直接继续未完成的选题创作 | 从首页点击选题到打开编辑 < 2 次点击 |
| G4 | 用户打开首页就知道今天必须做的 1-3 件事 | 今日待办 100% 来自系统自动计算（非示例） |
| G5 | 用户不用进数据复盘就能感知最近 7 天的内容表现 | 表现速览展示 Top 3 和异常标记 |

---

## 3. Non-Goals

| # | 不做什么 | 原因 |
|---|---------|------|
| N1 | 不实现日历的拖拽排期（在日历上拖动内容卡改日期） | v2.0 日历只读展示，排期操作在内容计划完成 |
| N2 | 不在首页直接新建/编辑内容策划卡 | 点击跳转到内容计划详情页编辑 |
| N3 | 不汇总跨选题空间的数据 | 保持"一个空间一个首页"的隔离逻辑 |
| N4 | 不在首页展示完整数据复盘图表（趋势图、对比图） | 表现速览只做 Top 3 + 异常标记，深度分析去数据复盘 |
| N5 | 不实现 AI 自动生成"今日建议"（如"建议今天发家居改造类内容"） | P2 规划 |
| N6 | 不实现推送通知/浏览器提醒 | 本地单机无推送机制 |

## 4. User Stories

### 4.1 数据总览

| 优先级 | 用户故事 |
|--------|---------|
| P0 | 作为自媒体运营，我希望在首页顶部看到总播放数、总点赞、总粉丝、总分享数（聚合所有自有账号），以便 3 秒内感知整体运营体量。 |
| P0 | 作为自媒体运营，我希望能看到本周已发布进度（如"本周已发布 2/5 条"），以便判断发布节奏是否跟得上计划。 |
| P1 | 作为自媒体运营，我希望看到各账号的粉丝趋势箭头（↑ / ↓ / →），以便一眼发现哪个账号在掉粉需要关注。 |
| P1 | 作为自媒体运营，我希望能看到"待补数据提醒"（已发布但未录入表现数据的内容数），以便不遗漏数据录入。 |

### 4.2 内容日历

| 优先级 | 用户故事 |
|--------|---------|
| P0 | 作为运营 3 个账号 × 3 个平台的自媒体人，我希望能在一张月视图日历上看到每天在哪个账号的哪个平台发布了什么内容，每种"账号×平台"组合用不同颜色标记，以便一眼看出发布分布是否均衡、是否存在某账号长期空档。 |
| P0 | 作为自媒体运营，我希望点击日历上某一天时，能展开看到当天发布的所有内容列表（标题 + 平台 + 账号），以便快速回顾。 |
| P0 | 作为自媒体运营，我希望能点击日历上任意日期添加自由文本记录（如"今天写了 3 小时脚本""和品牌方沟通合作"），以便日历不仅展示发布记录，也记录日常运营动作。 |
| P1 | 作为自媒体运营，我希望能切换周视图/月视图，以便按不同粒度查看发布节奏。 |
| P2 | 作为自媒体运营，我希望能看到日历上标记了"计划中但尚未发布"的内容（虚线圈/半透明），以便对比计划和实际。 |

### 4.3 选题流水线

| 优先级 | 用户故事 |
|--------|---------|
| P0 | 作为自媒体运营，我希望在首页看到正在创作中但尚未完成的选题列表（写作中 / 待排期状态），以便快速知道有哪些"半成品"需要继续推进。 |
| P0 | 作为自媒体运营，我希望每条选题显示标题、目标平台、已写进度（如文字/脚本/素材的完成情况）和最后编辑时间，以便判断哪个该优先完成。 |
| P1 | 作为自媒体运营，我希望点击选题卡片后直接跳转到该选题的编辑页，以便无缝继续创作。 |

### 4.4 今日待办

| 优先级 | 用户故事 |
|--------|---------|
| P0 | 作为自媒体运营，我希望首页展示"今天必须做的事"：今日排期发布的内容、逾期未发的内容、今天该补数据的内容——且这些全部由系统自动计算，不是固定示例。 |
| P0 | 作为自媒体运营，我希望对待办项进行"标记完成"或"推迟到明天"操作，以便 2 秒内完成每日任务管理。 |
| P1 | 作为自媒体运营，我希望能区分"今日必做"和"待处理"两个层级（前者逾期有后果，后者可灵活安排），以便优先处理紧急事项。 |

### 4.5 表现速览

| 优先级 | 用户故事 |
|--------|---------|
| P0 | 作为自媒体运营，我希望在首页看到最近 7 天表现最好的 Top 3 内容（按播放量/互动数排序），以便快速感知近期内容效果，不用进数据复盘。 |
| P0 | 作为自媒体运营，我希望能看到异常标记：超均值 2 倍的"爆款"和低于均值 50% 的"翻车"内容，以便及时分析原因。 |
| P1 | 作为自媒体运营，我希望能点击速览中的内容跳转到数据复盘查看完整分析。 |

### 4.6 灵感速递 & 快捷跳转（保留 v1.0）

| 优先级 | 用户故事 |
|--------|---------|
| P0 | 作为自媒体运营，我希望看到最新 3 条对标作品信号，以便感知竞品动态。（保留 v1.0） |
| P0 | 作为自媒体运营，我希望能一键跳转到灵感雷达、内容计划、数据复盘等深度模块。（保留 v1.0） |
| P0 | 作为自媒体运营，我希望点击"刷新雷达"后获得操作反馈。（保留 v1.0） |

### 5.2 数据总览卡片（Must-Have P0）

#### 5.2.1 四大核心指标

| 指标 | 数据来源 | 计算方式 |
|------|---------|---------|
| 总播放 | ContentPerformance 表 | SUM(plays)，当前空间所有自有账号已发布内容的播放量合计 |
| 总点赞 | ContentPerformance 表 | SUM(likes) |
| 总粉丝 | 需新增字段或对比机制 | 取各账号最近一次录入的粉丝数合计 |
| 总分享 | ContentPerformance 表 | SUM(shares) |

**依赖**：数据复盘模块的内容表现数据。数据未打通时，指标卡片显示"暂无数据"引导。（数据依赖表见第 6 节，手动管理）

**验收框架（MVP 级别）**：
- [ ] 指标卡片位置和样式正确渲染
- [ ] 有数据时展示聚合数值（万级单位）
- [ ] 无数据时显示占位引导，不空白报错
- [ ] 数据更新后首页刷新可见

#### 5.2.2 本周发布进度条

**计算方式**：本周已标记"已发布"的内容数 / 本周计划发布数（取内容计划中本周排期的内容数）。

**依赖**：内容计划模块的真实排期数据。

**验收框架**：
- [ ] 有排期数据时正确计算并展示进度条
- [ ] 本周无排期时不崩溃，显示引导
- [ ] 已发布数超过计划数时进度条满格

#### 5.2.3 各账号粉丝趋势箭头（Nice-to-Have P1）

每个自有账号显示粉丝数 + 趋势箭头（对比上周同期数据）：

- ↑ 绿色：粉丝增长 > 5%
- → 灰色：粉丝变化 ±5% 以内
- ↓ 红色：粉丝下降 > 5%

**验收框架**：
- [ ] 有对比数据时正确展示箭头方向和颜色
- [ ] 无历史数据不显示箭头

#### 5.2.4 待补数据提醒（Nice-to-Have P1）

**计算方式**：内容计划中状态为"已发布"但无表现数据的内容数。

**验收框架**：
- [ ] 有遗漏数据时显示数量和 ⚠️ 标记
- [ ] 无遗漏时显示 ✓
- [ ] 点击跳转到数据录入

### 5.3 内容日历（Must-Have P0）

#### 5.3.1 日历视图

**默认视图**：月视图（当月日历）。可切换周视图（P1）。

**数据来源**：内容计划中状态为"已发布"的内容卡及其 `target_publish_date` 和 `target_account_id`。

**颜色规则**：每个"自有账号 × 平台"组合分配一个独特色块。系统自动为每个激活的账号×平台组合从预设色板中分配颜色。

**色板预设（9 色）**：

| 序号 | 颜色 | 适用场景 |
|------|------|---------|
| 1 | #EF4444 红 | 主号-小红书 |
| 2 | #F97316 橙 | 主号-抖音 |
| 3 | #EAB308 黄 | 主号-视频号 |
| 4 | #22C55E 绿 | 小号-小红书 |
| 5 | #06B6D4 青 | 小号-抖音 |
| 6 | #3B82F6 蓝 | 小号-视频号 |
| 7 | #8B5CF6 紫 | 三号-小红书 |
| 8 | #EC4899 粉 | 三号-抖音 |
| 9 | #78716C 灰 | 三号-视频号 |

如果实际激活的组合少于 9 个，只展示对应颜色并在图例中标注。如果有超过 9 个组合，系统循环分配颜色并显示图例。

**日历格子展示**：
- 当天有发布：在日期格子内显示对应颜色的小圆点（一个或多个，按发布数量）
- 当天无发布：空白
- 当天有多条发布：多个圆点并排或堆叠
- 点击日期：弹出当天发布内容列表（P0）

**验收框架**：
- [ ] 日历正确渲染当月所有日期
- [ ] 有发布内容的日期显示对应颜色圆点
- [ ] 同日多平台发布时多个圆点正确排列
- [ ] 点击日期展开发布列表（标题 + 账号 + 平台）
- [ ] 日历翻页（上月/下月）数据正确加载
- [ ] 图例正确标注每个颜色对应的"账号-平台"
- [ ] 无数据时日历正常渲染，不报错

#### 5.3.2 计划中内容标记（Nice-to-Have P2）

已排期但未发布的内容在日历上以虚线圈或半透明圆点标记，与实际发布（实心圆点）区分。

#### 5.3.3 日历记录 / 备注（Must-Have P0）

日历不仅是"发布记录查看器"，更是自媒体运营者的每日日志。除了系统自动显示的发布记录外，用户可以在任意日期上手动添加自由文本记录。

**触发方式**：点击日历上任意日期 → 展开的详情面板中除发布列表外，下方有"记录/备注"区域。

**记录内容**：
- 自由文本（如"今天写了 3 小时脚本""和品牌方沟通了合作细节""今天研究了对标账号新套路"）
- 每条记录自动附带日期和创建时间
- 同一天可添加多条记录

**记录的作用**：
- 补全日历的信息密度 —— 不是每天都发内容，但每天都有运营动作
- 回顾时能看到"那天虽然没发视频，但做了 X 和 Y"
- 复盘周期时，日历记录可以作为补充上下文（"这周为什么只发了 2 条？因为周二周三都在写脚本"）

**展示方式**：
- 日历格子上：当天有记录的日期右上角显示 📝 小图标（区别于发布圆点）
- 点击日期后：先展示发布列表（如有），下方展示所有记录的列表，底部有"添加记录"输入框

**验收框架**：
- [ ] 点击日期展开 → 发布列表下方有"添加记录"入口
- [ ] 输入文字保存 → 该日期右上角出现 📝 标记
- [ ] 同一日期可追加多条记录，按创建时间排列
- [ ] 记录可删除

### 5.4 选题流水线（Must-Have P0）

#### 5.4.1 展示规则

**展示内容**：内容计划中状态为"选题池"或"已排期"但尚未发布的内容卡（即"进行中"的选题）。

**排序**：按最后编辑时间倒序（最近动过的排前面）。

**每条展示**：

| 字段 | 说明 |
|------|------|
| 标题 | 内容卡标题 |
| 状态 | "写作中"（选题池） / "待排期" / "已排期" |
| 目标平台 | 平台图标 |
| 进度摘要 | 基于内容卡字段推算：有标题=20%，有角度=40%，有脚本=60%，有素材=80%，已排期=90% |
| 最后编辑时间 | "2 天前""5 天前"等相对时间 |

**最多展示 5 条**，超出部分显示"查看全部 X 条选题 →"链接到内容计划。

**验收框架**：
- [ ] 有进行中选题时正确展示，按最后编辑时间排序
- [ ] 选题进度条正确显示
- [ ] 点击选题卡片跳转到内容计划
- [ ] 无选题时显示引导 + "新建选题"入口
- [ ] 超过 5 条时只展示最近 5 条 + "查看全部"

#### 5.4.2 进度计算逻辑

| 内容卡字段状态 | 进度贡献 | 
|-------------|---------|
| 有标题 | +20% |
| 有内容角度 | +20% |
| 有脚本/大纲 | +20% |
| 有关联素材 | +20% |
| 已设定目标发布时间 | +20% |

> 注：这个进度计算需要内容卡增加"脚本内容""素材关联"等字段，v2.0 如这些字段尚未建成，进度可以简化为"有标题 30% / 有角度 60% / 已排期 100%"三段式。

### 5.5 今日待办（Must-Have P0）

#### 5.5.1 自动生成规则

系统根据以下规则自动生成今日待办项：

| 规则 | 来源 | 层级 |
|------|------|------|
| 内容计划中排期日期 = 今天且未发布 | 内容卡 target_publish_date | 🔴 必须今天做 |
| 内容计划中排期日期 < 今天且未发布（逾期） | 内容卡 target_publish_date | 🔴 必须今天做 |
| 已发布超过 2 天但未录入表现数据 | 内容卡状态"已发布" + 无 ContentPerformance | 🔴 必须今天做 |
| 已发布超过 7 天但未完成复盘结论 | 内容卡状态"已发布" + 无 ReviewConclusion | 🟡 待处理 |
| 选题池中超过 14 天未更新的选题 | 内容卡状态"选题池" + updated_at | 🟡 待处理 |

**防重复**：同一内容卡触发的多个待办项去重，保留优先级高的。

**验收框架**：
- [ ] 有待办项时正确按规则生成（今日排期、逾期、数据待补）
- [ ] "必须今天做"和"待处理"正确分层展示
- [ ] 待办项去重（同一内容不重复出现）
- [ ] 点击"完成"项从列表移除，"推迟"项明天重现
- [ ] 误操作后提供短暂撤销（3 秒内）
- [ ] 无待办时显示"暂无必做事项"

#### 5.5.2 操作交互

每个待办项右侧有两个操作按钮：

| 操作 | 效果 |
|------|------|
| ✅ 完成 | 从列表中移除，记录操作时间 |
| ⏭️ 推迟 | 从今天列表中移除，明天重新出现 |

**验收框架**：
- [ ] 完成/推迟按钮正常交互
- [ ] 误操作撤销可用

### 5.6 表现速览（Must-Have P0）

#### 5.6.1 Top 3 内容

**数据来源**：ContentPerformance 表，筛选近 7 天内有数据录入的内容。

**排序**：默认按播放量排序，可切换为点赞数（P1）。

**每条展示**：

| 字段 | 来源 |
|------|------|
| 排名 | 1/2/3 |
| 内容标题 | ContentCard.title |
| 播放量 | SUM(plays) |
| 是否爆款/翻车标记 | 对比均值 |

**爆款/翻车判定**：

| 判定 | 条件 | 标记 |
|------|------|------|
| 🔥 爆款 | 播放量 ≥ 该账号近 10 条均值的 2 倍 | 橙色"爆款"标签 |
| ⚠️ 翻车 | 播放量 ≤ 该账号近 10 条均值的 50% | 红色"低于均值"标签 |
| — | 其余情况 | 无特殊标记 |

**验收框架**：
- [ ] 有数据时 Top 3 按播放量正确降序
- [ ] 爆款/翻车标签依据阈值正确标记
- [ ] 数据不足 3 条时只展示实际数量
- [ ] 无数据时显示引导，不报错

#### 5.6.2 跳转

点击 Top 内容 → 跳转数据复盘该内容的详情页。点击"查看完整复盘 →"→ 跳转数据复盘。

## 6. 数据依赖与前置条件（参考表，手动管理）

今日工作台本身不维护独立数据，所有数据聚合自其他模块。下表用于开发参考，各模块间的依赖关系由用户手动协调和导入：

| 区域 | 依赖模块 | 依赖状态 | 若依赖未就绪时的降级方案 |
|------|---------|---------|------------------------|
| 数据总览（四大指标） | 数据复盘 ContentPerformance | 待开发 | 显示引导文案 + "暂无数据" |
| 本周进度条 | 内容计划 ContentCard | 待开发 | 隐藏该模块 |
| 粉丝趋势箭头 | 数据复盘 + 历史粉丝对比 | 待开发 | 降级为 P1，先不做 |
| 内容日历 | 内容计划 ContentCard + OwnedAccount | 待开发 | 显示引导文案 + "暂无发布记录" |
| 日历记录/备注 | 无外部依赖（本地自由文本存储） | 无阻塞 | 可独立开发 |
| 选题流水线 | 内容计划 ContentCard | 待开发 | 显示引导文案 + "新建选题"入口 |
| 今日待办 | 内容计划 + 数据复盘 | 待开发 | 显示引导文案，无待办项 |
| 表现速览 | 数据复盘 ContentPerformance | 待开发 | 显示引导文案 + "暂无数据" |
| 灵感速递 | 灵感雷达 Post | 已就绪 | 无降级，v1.0 已可用 |

**关键路径**：今日工作台 v2.0 要真正可用，必须先完成"内容计划 v2.0"和"数据复盘 v2.0"的基础数据能力。建议将今日工作台 v2.0 作为这两个模块完成后的集成 sprint，分阶段点亮各区域。

## 7. Success Metrics

| 指标 | 定义 | 基线 | 目标 |

## 8. 用户路径

### 核心路径：每日打开工作台

```
1. 打开首页 → 数据总览：一眼看清总播放/点赞/粉丝/分享 + 本周进度
2. 扫一眼今日待办 → "必须今天做"有 2 项 → 发布内容 + 补数据
3. 看一眼内容日历 → 确认昨天发了什么、明天排了什么
4. 选题流水线 → "厨房收纳"写到一半 → 点击继续创作
5. 表现速览 → Top 1 《玄关收纳》爆了 → 点进去看详情
6. 灵感速递 → 竞品新发了条内容 → 点进去研究
```
