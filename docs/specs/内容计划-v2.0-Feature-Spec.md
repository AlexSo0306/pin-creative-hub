## 1. Problem Statement

v1.0 的内容计划是一个静态原型——展示了四列看板框架，但卡片写死在前端代码里，不可新增、编辑或持久化。自媒体运营者实际的工作流程是：AI 生成口播录制稿和三平台发布方案两份 Markdown 文档 → 粘贴到系统 → 拍摄制作 → 三平台差异化发布 → 回收数据复盘。当前没有地方承载这些真实产出。

**v2.0 要解决的核心问题**：让内容计划从"原型示意"升级为"内容项目管理中心"——每条内容是一个完整的项目卡片，承载口播录制稿 + 三平台发布方案两份 Markdown 文档，按"选题池 → 脚本库 → 制作中 → 已发布 → 已复盘"五状态流转，支持卡片拖动和真实数据持久化。

**真实用户工作流（基于苏师傅实际产出）**：

```
选题确定（如"双层芝士汉堡肉盖饭"）
  │
  ├── AI 生成两份文档
  │   ├── ① 口播录制稿（42s 精简版，含镜头脚本 + 录制要点 + 自检清单）
  │   └── ② 三平台发布方案（打分卡 + 标题库 + 7段镜次表 + 抖音/视频号/小红书分别文案）
  │
  ├── 粘贴进内容计划（进入"脚本库"状态）
  ├── 拍摄 + 剪辑（一天内完成，进入"制作中"状态）
  ├── 按三平台差异化时间发布
  │    抖音 17:30 → 视频号 18:00 → 小红书 19:00
  └── 发布后手动补录数据 → 复盘
```

**不解决的成本**：用户的录制稿和发布方案散落在本地文件夹，内容项目无法在工作台内集中管理，发布节奏和复盘数据完全脱节。

## 2. Goals

| # | 目标 | 衡量方式 |
|---|------|---------|
| G1 | 用户能创建内容项目卡片，持久化存储标题、状态和元数据 | 卡片数据重启后不丢失 |
| G2 | 用户能粘贴 AI 生成的两份 Markdown 文档到卡片中，在工作台内直接阅读 | 文档正确渲染 Markdown 格式 |
| G3 | 用户能拖动卡片在五状态看板间流转，直观管理内容进度 | 拖动后状态正确更新 |
| G4 | 用户能记录三平台各自的发布链接和时间 | 每个平台可独立填写 |
| G5 | 用户能从已发布内容跳转到数据复盘补充数据 | 一键跳转数据录入 |

---

## 3. Non-Goals

| # | 不做什么 | 原因 |
|---|---------|------|
| N1 | 不内置 Markdown 编辑器（如实时预览编辑器） | v2.0 文档为"粘贴后只读展示"，编辑在外部 AI 工具完成再粘入；P2 加在线编辑 |
| N2 | 不实现灵感转选题的数据连接 | 灵感雷达 v2.0 中已决策 MVP 不做连接，用户手动创建内容卡 |
| N3 | 不存储视频文件和素材附件 | 内容计划管文字，媒体文件是本地文件路径引用 |
| N4 | 不自动生成脚本或发布方案 | AI 生成在外部完成，系统只做存储和展示 |
| N5 | 不实现发布到第三方平台 | 产品边界外 |
| N6 | 不汇总跨选题空间的内容看板 | 保持空间隔离 |

## 4. User Stories

### 4.1 看板与卡片管理

| 优先级 | 用户故事 |
|--------|---------|
| P0 | 作为自媒体运营，我希望能看到内容在"选题池 → 脚本库 → 制作中 → 已发布 → 已复盘"五列看板上的分布，以便掌握所有内容的进度。 |
| P0 | 作为自媒体运营，我希望能创建一条新内容卡片（填写标题），它出现在选题池中，以便把模糊想法沉淀下来。 |
| P0 | 作为自媒体运营，我希望能在列之间拖动卡片来变更状态（如选题池拖到脚本库），以便推进内容进入下一阶段。 |
| P0 | 作为自媒体运营，我希望能编辑卡片标题或删除不再需要的卡片，以便保持看板整洁。 |
| P1 | 作为自媒体运营，我希望能按平台筛选看板（只看抖音内容 / 小红书内容），以便按渠道管理排期。 |

### 4.2 文档承载

| 优先级 | 用户故事 |
|--------|---------|
| P0 | 作为自媒体运营，我希望能把 AI 生成的口播录制稿（Markdown）粘贴到内容卡片的"录制稿"区域，系统正确渲染标题、列表、表格等格式，以便在工作台内直接阅读脚本而不用打开外部文件。 |
| P0 | 作为自媒体运营，我希望能把 AI 生成的三平台发布方案（Markdown）粘贴到内容卡片的"发布方案"区域，以便在策划和排期时随时查阅标题库、镜次表和平台文案。 |
| P0 | 作为自媒体运营，我希望能看到卡片上是否已有录制稿和发布方案（有/无标记），以便一眼判断该选题的内容完整度。 |
| P1 | 作为自媒体运营，我希望能一键清空并重新粘贴文档（覆盖更新），以便 AI 重新生成了更好的版本后直接替换。 |

### 4.2.1 账号归属

| 优先级 | 用户故事 |
|--------|---------|
| P0 | 作为同时运营 3 个不同方向账号的自媒体人，我希望在选题池创建卡片时选择这条内容属于哪个账号，以便在一个看板里区分"苏师傅的美食选题"和"拼好家的家居选题"不会混在一起。 |
| P0 | 作为自媒体运营，我希望看板上每条卡片都显示所属账号的名称和颜色标记，以便一眼区分不同账号的内容分布。 |
| P0 | 作为自媒体运营，我希望在五列看板顶部按账号切换视图（全部/苏师傅/拼好家主号/拼好家小号），以便只看某个账号的内容管线。 |
| P1 | 作为自媒体运营，我希望已创建的卡片可以修改账号归属（如选题方向调整），以便卡片不因选错账号而需要删除重建。

### 4.3 制作进度

| 优先级 | 用户故事 |
|--------|---------|
| P0 | 作为自媒体运营，我希望能将"制作中"状态的卡片标上进度标签（拍摄中 / 剪辑中 / 待发布），以便在同时有多条内容制作中时区分阶段。 |
| P1 | 作为自媒体运营，我希望能看到某卡片在"制作中"状态停留了多久，以便发现堵在制作环节的内容。 |

### 4.4 发布记录

| 优先级 | 用户故事 |
|--------|---------|
| P0 | 作为自媒体运营，我希望能为每条已发布内容记录三个平台各自的发布链接和发布时间，以便后续从卡片直接跳转到平台作品。 |
| P0 | 作为自媒体运营，我希望能填写本次发布的标题（每个平台不同），以便对应到发布方案中生成的标题库。 |
| P1 | 作为自媒体运营，我希望能一键标记"已发布"并自动填入今日日期，减少手动输入。 |

### 4.5 与数据复盘联动

| 优先级 | 用户故事 |
|--------|---------|
| P0 | 作为自媒体运营，我希望能从已发布卡片一键跳转到数据复盘录入表现数据（播放量、点赞等），以便完成运营闭环。 |
| P0 | 作为自媒体运营，我希望卡片在完成复盘后状态变为"已复盘"，并在卡片上展示关键指标摘要（总播放量、互动率）。 |

**五状态定义**：

| 状态 | 含义 | 进入条件 | 去往 |
|------|------|---------|------|
| 选题池 | 模糊想法，还没写脚本 | 手动创建 / 灵感启发 | 脚本库、删除 |
| 脚本库 | 两份 AI 文档已粘贴，脚本定稿，等待制作 | 从选题池拖动 | 制作中、退回选题池 |
| 制作中 | 拍摄+剪辑进行中 | 从脚本库拖动 | 已发布、退回脚本库 |
| 已发布 | 已在平台发布，链接已记录 | 从制作中拖动 + 填写链接 | 已复盘 |
| 已复盘 | 数据回收完毕，复盘结论已写 | 从已发布拖动（需数据复盘完成） | 知识资产 |

**验收框架**：
- [ ] 五列看板正确展示，每列显示卡片数和卡片
- [ ] 拖动卡片到目标列，状态正确更新
- [ ] 卡片按最后编辑时间排序（最近动过的在上面）
- [ ] 空列显示引导（"选题池为空，去灵感雷达找找灵感？"）

#### 5.1.1 账号切换（Must-Have P0）

看板顶部有账号切换栏，支持按账号过滤看板内容：

| 选项 | 行为 |
|------|------|
| 全部 | 展示当前选题空间下所有账号的内容卡片 |
| 苏师傅爱做饭 | 只展示属于该账号的卡片 |
| 英爱家38平 | 只展示属于该账号的卡片 |
| 游泳健身了解一下 | 只展示属于该账号的卡片 |
| ⚙️ 管理 | 跳转到账号矩阵模块，在那边添加/修改/停用账号 |

**关键设计**：账号的增删改在**账号矩阵模块**统一管理。内容计划只做读取和筛选，不做账号管理。账号列表从账号矩阵动态读取，不硬编码。

**切换行为**：
- 切换账号后，五列看板只展示该账号的内容
- 当前选中的账号高亮显示
- 默认状态："全部"
- 账号列表为空时，显示"暂无自有账号，点击 ⚙️ 去账号矩阵添加"

**验收框架**：
- [ ] 账号列表从账号矩阵模块读取（OwnedAccount 中 status=运营中 的账号）
- [ ] 切换账号后看板内容正确筛选
- [ ] 选"全部"时所有卡片可见，每个卡片显示所属账号名和颜色标记
- [ ] 账号矩阵中暂无自有账号时，显示引导"请先在账号矩阵中添加自有账号"

### 5.2 新建选题（Must-Have P0）

点击"+ 新建选题"按钮 → 弹出简洁表单：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 内容标题 | 文本 | 是 | 如"双层芝士汉堡肉盖饭" |
| 所属账号 | 下拉选择 | 是 | 从账号矩阵读取，如"苏师傅爱做饭 / 英爱家38平 / 游泳健身了解一下" |
| 主推平台 | 下拉选择 | 否 | 抖音 / 小红书 / 视频号（可选，后期可改） |

保存后卡片出现在选题池中，显示账号颜色标记。

**验收框架**：
- [ ] 新建时账号下拉可选范围为自有账号（来自账号矩阵）
- [ ] 未选择账号时保存按钮置灰，提示"请选择所属账号"
- [ ] 保存后卡片上正确显示账号名称和颜色标记

### 5.3 文档承载（Must-Have P0）

#### 5.3.1 粘贴文档

**触发方式**：在卡片详情中切换到"🎬 录制稿"或"📋 发布方案"Tab → 点击"粘贴文档" → 弹出文本区。

**行为**：
- 支持粘贴纯文本和 Markdown
- 保存后切换为渲染视图（标题、列表、表格、加粗等正确展示）
- 点击"编辑"回到文本编辑模式（textarea）
- 点击"清空重粘"清空当前内容并进入编辑模式

**验收框架**：
- [ ] Markdown 基本语法正确渲染（标题 #、列表 -、表格 |、加粗 **、引用 >）
- [ ] 表格超过 6 列时水平滚动，不溢出
- [ ] 文档为空时显示引导"点击粘贴 AI 生成的录制稿"
- [ ] 粘贴后自动保存（或点击保存按钮）
- [ ] 卡片看板视图中自动更新文档图标（📄/📋）

#### 5.3.2 文档状态标记

看板卡片上用图标标记文档存在状态：

| 图标 | 含义 |
|------|------|
| 📄 | 有录制稿 |
| 📋 | 有发布方案 |
| 📄📋 | 两份都有 |
| — | 两份都没有（选题池阶段） |

**验收框架**：
- [ ] 卡片上正确显示文档图标
- [ ] 更新文档后图标实时刷新

### 5.4 制作进度标签（Must-Have P0）

仅在"制作中"状态的卡片上可见。三个可选标签，手动切换：

| 标签 | 含义 | 卡片上显示 |
|------|------|----------|
| 🎬 拍摄中 | 正在拍摄素材 | 标签 + 🎬 图标 |
| ✂️ 剪辑中 | 素材已拍完，正在剪辑 | 标签 + ✂️ 图标 |
| ✅ 待发布 | 成品已完成，等待发布时间 | 标签 + ✅ 图标 |

**交互**：卡片上点击标签 → 弹出下拉选择。不强制选择，默认为空（无标签）。

**验收框架**：
- [ ] 只有"制作中"状态的卡片显示进度标签
- [ ] 点击标签可切换三个值或置空
- [ ] 切换到其他状态后标签自动清除

### 5.5 发布记录（Must-Have P0）

#### 5.5.1 填写发布信息

**触发**：卡片详情 → "📊 发布记录"Tab → 填写各平台信息。

**字段（每个平台独立）**：

| 字段 | 类型 | 说明 |
|------|------|------|
| 发布链接 | URL | 平台作品跳转链接 |
| 发布时间 | 日期+时间 | 实际发布时间 |
| 发布标题 | 文本 | 该平台使用的标题（不同于看板标题） |

**验收框架**：
- [ ] 每个平台独立填写，互不影响
- [ ] 链接可点击跳转（新窗口打开）
- [ ] 三个平台都不填时也可标记"已发布"

#### 5.5.2 标记已发布

**触发**：发布记录 Tab 中点击"标记为已发布"按钮。

**行为**：
- 卡片状态从"制作中"变为"已发布"
- 未填的发布时间自动填入当前日期
- 卡片从"制作中"列移到"已发布"列

**验收框架**：
- [ ] 标记后状态正确变更
- [ ] 可回溯：从"已发布"拖回"制作中"时发布记录不丢失

## 6. 数据模型

### 6.1 ContentCard 对象

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string (uuid) | 是 | 主键 |
| `space_id` | string | 是 | 所属选题空间 |
| `title` | string | 是 | 内容标题 |
| `account_id` | string | 是 | 所属自有账号 ID（来自账号矩阵），新建时必选 |
| `account_color` | string | 否 | 账号标记颜色（从账号矩阵同步） |
| `status` | enum | 是 | `idea` / `scripted` / `producing` / `published` / `reviewed` |
| `category` | string? | 否 | 内容方向，如"美食""家居" |
| `script_body` | string? (Markdown) | 否 | 口播录制稿 Markdown 内容 |
| `script_updated_at` | ISO 8601? | 否 | 录制稿最后更新时间 |
| `publish_plan_body` | string? (Markdown) | 否 | 三平台发布方案 Markdown 内容 |
| `publish_plan_updated_at` | ISO 8601? | 否 | 发布方案最后更新时间 |

### 6.2 PlatformPublishInfo 对象（嵌入 ContentCard）

| 字段 | 类型 | 说明 |
|------|------|------|
| `platform` | enum | douyin / xiaohongshu / shipinhao |
| `publish_url` | string? | 发布链接 |
| `publish_time` | ISO 8601? | 实际发布时间 |
| `publish_title` | string? | 该平台使用的标题 |

每个 ContentCard 包含三个 PlatformPublishInfo（每个平台一个）。

### 6.3 ContentPerformance 关联

已复盘状态时，ContentCard 关联来自数据复盘模块的 ContentPerformance 记录。关联方式：`content_card_id` 外键。

### 6.4 API 规划

| 方法 | 接口 | 作用 |
|------|------|------|
| GET | `/api/content-cards?space_id=X` | 获取卡片列表（支持 status/platform 筛选） |
| POST | `/api/content-cards` | 创建卡片 |
| PUT | `/api/content-cards/:id` | 更新基本信息 |
| PATCH | `/api/content-cards/:id/status` | 变更状态（拖动） |
| PATCH | `/api/content-cards/:id/script` | 更新录制稿 |
| PATCH | `/api/content-cards/:id/publish-plan` | 更新发布方案 |
| PATCH | `/api/content-cards/:id/publish-info` | 更新发布记录 |
| DELETE | `/api/content-cards/:id` | 软删除 |

## 7. Success Metrics

| 指标 | 定义 | 目标 |
|------|------|------|
| 看板活跃数 | 每周有卡片状态变更的卡片数 | > 5 |
| 文档承载率 | 脚本库列中有录制稿的卡片数 / 脚本库总数 | > 90% |
| 状态流转速度 | 从选题池创建到已发布的平均天数 | < 14 天 |
| 发布记录完整率 | 三个平台链接全部填写的已发布卡片数 / 总已发布数 | > 80% |
| 复盘完成率 | 已复盘卡片数 / 已发布满 7 天的卡片数 | > 70% |
