> 文档类型：Feature Spec / 可执行 PRD
> 所属产品：拼好家运营创作中心
> 关联模块：数据复盘
> 版本：v2.0
> 日期：2026-08-04
> 状态：待评审
> 前置文档：[产品总览](../../拼好家内容创作中心/README-产品总览.md) | [现状基线](as-built-2026-09-21.md)

## 1. Problem Statement

v1.0 的数据复盘展示了周/月切换、互动数据、Top 内容、复盘结论的框架，但所有指标和结论都是固定示例，不来自真实数据。自媒体运营者发布内容后需要手动回收各平台表现数据（播放、点赞、评论、收藏、分享、涨粉、咨询），判断什么选题有效、什么开头转化好，并沉淀方法。如果数据不回收、不复盘，内容计划里"已发布"的内容永远走不到"已复盘"，运营闭环断裂。

**v2.0 要解决的核心问题**：让数据复盘成为"内容表现数据中心"——用户从内容计划跳转过来为每条已发布内容补录三平台的表现数据，系统自动计算衍生指标，按周期/账号/平台聚合查看，并写下复盘结论沉淀到知识资产。

**真实业务场景**：
- 一条内容（如"双层芝士汉堡肉盖饭"）在抖音、小红书、视频号三个平台差异化发布
- 每个平台的数据独立：抖音看播放量，小红书看阅读+收藏，视频号看转发
- 三个账号（苏师傅爱做饭/英爱家38平/游泳健身了解一下）各自的数据要能分开看
- 每周/每月要能回顾：哪些内容爆了、哪些翻车了、下周怎么调整

**不解决的成本**：发布后数据散落在各平台后台，无法集中对比；复盘靠记忆，有效方法无法沉淀复用；内容计划中"已发布"堆积无法进入"已复盘"。

## 2. Goals

| # | 目标 | 衡量方式 |
|---|------|---------|
| G1 | 用户能为每条已发布内容补录三平台表现数据 | 数据录入后持久化，内容计划卡片联动 |
| G2 | 系统自动计算互动率、收藏率、线索转化率等衍生指标 | 录入后自动计算展示 |
| G3 | 用户能按周期（周/月）× 账号 × 平台查看聚合数据 | 多维筛选可用 |
| G4 | 用户能识别 Top 内容和异常内容（爆款/翻车） | 自动标记，无需人工比对 |
| G5 | 用户能写复盘结论并一键沉淀到知识资产 | 沉淀操作 1 次点击 |

---

## 3. Non-Goals

| # | 不做什么 | 原因 |
|---|---------|------|
| N1 | 不自动从平台抓取数据 | 需平台 API，产品边界外；v2.0 手动录入 |
| N2 | 不实现 AB 测试对比分析 | v2.0 先做数据录入和基础统计 |
| N3 | 不做跨选题空间对比 | 每个空间独立复盘 |
| N4 | 不生成自动复盘报告（PDF 导出） | P2 规划 |
| N5 | 不做异常指标自动推送提醒 | 无推送机制，看板标记即可 |
| N6 | 不在复盘模块内管理内容卡片 | 内容卡片在内容计划，这里只做数据 |

## 4. User Stories

### 4.1 数据录入

| 优先级 | 用户故事 |
|--------|---------|
| P0 | 作为自媒体运营，我希望能从内容计划的"已发布"卡片跳转到数据录入页，为这条内容填写三平台各自的表现数据（播放量、点赞、评论、收藏、分享），以便集中回收数据。 |
| P0 | 作为自媒体运营，我希望能录入每条内容带来的涨粉数和有效咨询数（私信数），以便衡量内容的转化价值。 |
| P0 | 作为自媒体运营，我希望系统自动计算互动率、收藏率、线索转化率，以便不用自己算。 |
| P0 | 作为自媒体运营，我希望能看到哪些已发布内容还没录入数据（待补数据清单），以便不遗漏。 |
| P1 | 作为自媒体运营，我希望能对同一条内容多次录入数据（如发布后第 1 天、第 7 天各录一次），以便追踪数据变化趋势。 |

### 4.2 数据查看

| 优先级 | 用户故事 |
|--------|---------|
| P0 | 作为自媒体运营，我希望能按周/月切换复盘周期，以便按运营节奏回顾。 |
| P0 | 作为自媒体运营，我希望能按账号（苏师傅/英爱家38平/游泳健身）筛选数据，以便分别评估每个账号的表现。 |
| P0 | 作为自媒体运营，我希望能按平台（抖音/小红书/视频号）筛选数据，以便对比不同平台的表现差异。 |
| P0 | 作为自媒体运营，我希望能看到 Top 内容排行（按播放量/点赞/咨询排序），以便识别可复用的内容模式。 |
| P0 | 作为自媒体运营，我希望爆款（超均值 2 倍）和翻车（低于均值 50%）内容自动标记，以便一眼识别异常。 |
| P1 | 作为自媒体运营，我希望能看到指标的趋势变化（周与周对比），以便判断运营是在上升还是下滑。 |

### 4.3 复盘结论

| 优先级 | 用户故事 |
|--------|---------|
| P0 | 作为自媒体运营，我希望能针对每个周期写下复盘结论：哪些标题/开头/CTA 有效、哪些选题该放弃、下周改进方向。 |
| P0 | 作为自媒体运营，我希望能将有效的规律一键沉淀为知识资产，以便团队复用。 |
| P1 | 作为自媒体运营，我希望完成复盘后，内容计划的对应卡片自动变为"已复盘"状态。 |

## 5. Requirements

### 5.1 数据录入（Must-Have P0）

#### 5.1.1 触发入口

| 入口 | 位置 |
|------|------|
| 内容计划 → 已发布卡片 → "补数据"按钮 | 跳转到本内容的录入页 |
| 数据复盘 → "待补数据"清单 → 点击某条 | 跳转到该内容的录入页 |

#### 5.1.2 录入表单

每条内容按平台分组录入。表单结构：

```
┌─ 数据录入：双层芝士汉堡肉盖饭 ─────────────────┐
│ 所属账号：🟠 苏师傅爱做饭                     │
│                                              │
│ ┌─ 抖音 ───────────────────────────────────┐ │
│ │ 播放量 [52000]  点赞 [3240]               │ │
│ │ 评论 [156]     收藏 [892]  分享 [43]      │ │
│ │ 涨粉 [35]      咨询/私信 [12]             │ │
│ │ 数据采集日期 [2026-08-04]                │ │
│ └──────────────────────────────────────────┘ │
│ ┌─ 小红书 ─────────────────────────────────┐ │
│ │ 阅读量 [18000] 点赞 [2100]  ...           │ │
│ └──────────────────────────────────────────┘ │
│ ┌─ 视频号 ─────────────────────────────────┐ │
│ │ 播放量 [8000] 点赞 [600]   ...            │ │
│ └──────────────────────────────────────────┘ │
│                                              │
│ 自动计算：                                   │
│ 抖音互动率 8.3% | 小红书收藏率 12.1% | 线索 12 │
│                                              │
│ [保存数据]  [保存并标记已复盘]                │
└──────────────────────────────────────────────┘
```

**每个平台的字段**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 播放量/阅读量 | 整数 | 否 | 抖音/视频号用播放，小红书用阅读 |
| 点赞数 | 整数 | 否 | |
| 评论数 | 整数 | 否 | |
| 收藏数 | 整数 | 否 | |
| 分享数 | 整数 | 否 | |
| 涨粉数 | 整数 | 否 | 该内容带来的新增关注 |
| 咨询/私信数 | 整数 | 否 | 业务转化线索 |
| 数据采集日期 | 日期 | 是 | 默认今天 |

**自动计算指标**：

| 指标 | 公式 |
|------|------|
| 互动率 | (点赞+评论+收藏+分享) / 播放量 × 100% |
| 收藏率 | 收藏数 / 播放量 × 100% |
| 线索转化率 | 咨询数 / 播放量 × 100% |

**验收框架**：
- [ ] 从内容计划"补数据"跳转后，表单预填内容标题和账号
- [ ] 三个平台独立填写，可只填有发布的平台
- [ ] 采集日期默认今天，可改
- [ ] 保存后数据持久化，重新打开表单可见
- [ ] 播放量为 0 时衍生指标显示"—"，不报错
- [ ] 同平台重复录入时按采集日期区分（P1 多次录入）

### 5.2 待补数据清单（Must-Have P0）

**数据来源**：内容计划中状态为"已发布"但无任何平台数据记录的内容。

**展示**：

```
待补数据 (3)
  🟠 双层芝士汉堡肉盖饭   已发布 3 天   [去补数据]
  🔵 阳台改造方案        已发布 5 天   [去补数据]
  🟢 晨跑 30 天打卡      已发布 8 天   [去补数据]
```

**验收框架**：
- [ ] 已发布未录数据的内容出现在清单中
- [ ] 显示已发布天数，超过 7 天高亮提示"数据过期"
- [ ] 点击跳转到对应内容的数据录入页

### 5.3 复盘看板（Must-Have P0）

#### 5.3.1 筛选器

```
[周 ▾] [8月第1周 ▾]   [全部账号 ▾] [全部平台 ▾]
```

| 筛选维度 | 选项 |
|---------|------|
| 周期 | 周 / 月（默认周） |
| 周期范围 | 可前后切换，默认当前周期 |
| 账号 | 全部 / 苏师傅爱做饭 / 英爱家38平 / 游泳健身了解一下 |
| 平台 | 全部 / 抖音 / 小红书 / 视频号 |

#### 5.3.2 看板内容

```
┌─ 周期摘要 ──────────────────────────────────┐
│ 发布 4 条 | 总播放 128K | 总互动 9.8K |     │
│ 总涨粉 320 | 总咨询 28 | 平均互动率 7.6%     │
└─────────────────────────────────────────────┘
┌─ Top 内容 ────────────┬─ 异常标记 ──────────┐
│ 1. 🔥《玄关收纳》       │ 🔥 爆款 ×2         │
│    播放 52K · 抖音      │   《玄关收纳》     │
│ 2. 《厨房收纳》         │   超均值 320%      │
│    播放 38K · 小红书    │                    │
│ 3. 《客厅配色》         │ ⚠️ 翻车 ×1        │
│    播放 12K · 视频号    │   《客厅配色》     │
│                        │   低于均值 60%     │
└────────────────────────┴────────────────────┘
┌─ 数据明细表（可展开） ───────────────────────┐
│ 内容 | 平台 | 播放 | 点赞 | 互动率 | 咨询   │
│ ...                                          │
└──────────────────────────────────────────────┘
```

**爆款/翻车判定**（沿用灵感雷达的阈值逻辑）：

| 判定 | 条件 | 标记 |
|------|------|------|
| 🔥 爆款 | 播放量 ≥ 该账号近 10 条均值的 2 倍 | 橙色"爆款"标签 |
| ⚠️ 翻车 | 播放量 ≤ 该账号近 10 条均值的 50% | 红色"低于均值"标签 |
| — | 其余情况 | 无标记 |

**验收框架**：
- [ ] 周期、账号、平台三个筛选器独立生效
- [ ] 周期摘要数据随筛选条件变化
- [ ] Top 3 按播放量降序，点击跳转内容详情
- [ ] 爆款/翻车自动标记，阈值默认 2 倍/50%
- [ ] 当前周期无数据时显示"本周期暂无已发布内容"
- [ ] 筛选出某账号无数据时显示空状态引导

### 5.4 复盘结论（Must-Have P0）

#### 5.4.1 写结论

每个复盘周期（周/月）底部有一个"复盘结论"区域，用户在周期切换后为每个周期独立填写。

**字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| 有效标题模式 | 文本 | 本周表现好的标题有什么共性？ |
| 有效开头模式 | 文本 | 什么开头带来高完播/高互动？ |
| 有效 CTA 模式 | 文本 | 什么转化动作带来咨询？ |
| 可放弃选题类型 | 文本 | 哪些选题表现持续不佳？ |
| 下周改进方向 | 文本 | 1-3 条下周动作 |
| 沉淀为知识资产 | 开关 | 勾选后将以上内容沉淀到知识资产 |

**验收框架**：
- [ ] 每个周期独立保存结论，切换周期不丢失
- [ ] 未写结论的周期显示"本周期尚未写复盘结论"
- [ ] 勾选"沉淀为知识资产"保存后，知识资产模块新增一条"复盘"分类的资产

#### 5.4.2 标记内容已复盘

在数据录入页或明细表中，可将某条内容标记为"已复盘"，同步回写内容计划，卡片状态从"已发布"变为"已复盘"。

**验收框架**：
- [ ] 标记"已复盘"后，内容计划对应卡片自动移到"已复盘"列
- [ ] 卡片上展示复盘摘要（总播放量、互动率）

### 5.5 与今日工作台联动（Must-Have P0）

| 表现速览（近 7 天 Top 3 + 异常标记） | 本模块数据 |
| 待补数据提醒 | 本模块待补清单 |

## 6. 数据模型

### 6.1 ContentPerformance 对象

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string (uuid) | 是 | 主键 |
| `content_card_id` | string | 是 | 关联内容计划卡片 |
| `platform` | enum | 是 | douyin / xiaohongshu / shipinhao |
| `record_date` | date | 是 | 数据采集日期 |
| `plays` | int? | 否 | 播放量/阅读量 |
| `likes` | int? | 否 | 点赞数 |
| `comments` | int? | 否 | 评论数 |
| `bookmarks` | int? | 否 | 收藏数 |
| `shares` | int? | 否 | 分享数 |
| `followers_gained` | int? | 否 | 涨粉数 |
| `leads` | int? | 否 | 咨询/私信数 |
| `created_at` | ISO 8601 | 是 | 记录时间 |

**唯一性**：`content_card_id + platform + record_date` 唯一（同一天同一平台只录一次，多次录入用不同 record_date）。

### 6.2 ReviewConclusion 对象

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string (uuid) | 主键 |
| `space_id` | string | 所属空间 |
| `period_type` | enum | week / month |
| `period_start` | date | 周期开始 |
| `period_end` | date | 周期结束 |
| `effective_titles` | string? | 有效标题模式 |
| `effective_openings` | string? | 有效开头模式 |
| `effective_ctas` | string? | 有效 CTA 模式 |
| `abandon_topics` | string? | 可放弃选题 |
| `next_actions` | string? | 下周动作 |
| `created_at` | ISO 8601 | 记录时间 |

**唯一性**：`space_id + period_type + period_start` 唯一。

### 6.3 API 规划

| 方法 | 接口 | 作用 |
|------|------|------|
| GET | `/api/performance?content_card_id=X` | 获取内容的表现数据 |
| POST | `/api/performance` | 录入/更新表现数据 |
| GET | `/api/performance/pending` | 待补数据清单 |
| GET | `/api/performance/review?period=week&start=X` | 周期聚合数据（含 Top 和异常） |
| PUT | `/api/review-conclusion/:id` | 保存复盘结论 |
| POST | `/api/review-conclusion` | 新建复盘结论 |
| POST | `/api/content-cards/:id/reviewed` | 标记内容已复盘（回写内容计划） |

## 7. Success Metrics

| 指标 | 定义 | 目标 |
|------|------|------|
| 数据录入完成率 | 已录数据的已发布内容数 / 总已发布数 | > 80% |
| 数据及时率 | 发布后 7 天内完成录入的比例 | > 90% |
| 复盘完成率 | 有结论的周期数 / 总运营周期数 | > 80% |
| 复盘转资产率 | 沉淀为知识资产的结论数 / 总结论数 | > 50% |
| 爆款识别率 | 看板标记的爆款与用户人工确认的一致率 | > 90% |

## 8. 已知问题

| 优先级 | 问题 | 影响 |
|--------|------|------|
| P0 | v1.0 所有数据为固定示例 | 完全无法用于真实复盘 |
| P0 | 无真实发布记录可复盘 | 数据复盘依赖内容计划先建成 |
| P1 | 平台指标不可比（抖音播放 vs 小红书阅读） | 跨平台对比需提示口径差异 |
| P1 | 手动录入依赖用户习惯 | 需要待补清单和今日工作台提醒驱动 |
