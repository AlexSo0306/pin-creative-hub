## 2. 走查判定维度（逐页核对清单）

每个维度均要给出：**页面 → 文件位置（行号/选择器）→ 规范条款 → 状态（符合/偏离）→ 严重度 → 修复建议**。

### A. 公共壳层一致性（P0，已验证规则）
- [ ] `.app-shell` 栅格为 `248px 1fr`（§2.1）
- [ ] 侧边栏结构 `aside.sidebar > .logo + nav(6 项) + .theme-switch + .side-cta + .side-foot`，当前页 `a.on` + `aria-current="page"`（§2.1）
- [ ] 主区为 `.app-main > main#content`（§2.1，注意 `id="content"` 必须存在——bento 主题用 `#content` 定位）
- [ ] 命令条头（§8.2）结构、eyebrow 字号/大小写/accent 色一致
- [ ] `footer.pagefoot` 存在
- [ ] 主题切换器 5 项齐全、`localStorage` 键 `phj-workbench-theme`、`applyTheme/initTheme` 保留（§4）

### B. 设计令牌（P0）
- [ ] 首个 `<style>` 内 `:root` 块与规范 §1.1 **逐字一致**（含 `--c1..--c9`）
- [ ] `:root` 之外无裸 hex，一律 `var(--*)`（§1.1 / §8.4 P0）
- [ ] 9 色语义只用于「账号 × 平台」维度（§1.3，不得挪用给分类/状态）
- [ ] accent 预算 ≤ 2 处主强调 / 屏（§1.2）

### C. 组件规范（P1）
- [ ] `.btn-primary` 视觉与基准一致：**白底黑字，hover 变 accent 蓝底白字**（§3.1）——重点核对 4 个页面当前为「accent 蓝底」的分叉
- [ ] `.btn-secondary` / `.btn-ghost` / `.btn-icon`（带 aria-label）/ `.btn.on` 选中态（§3.1）
- [ ] `.card` 为 `--surface` 底 + `1px var(--border)` + `--radius-lg` + `--elev-raised`（§3.2）
- [ ] 指标卡 `.metric`、进度条 `.progress`、日历 `.cal-cell`（含 `aria-label`）结构（§3.4/3.5/3.6）
- [ ] 输入 `.input`：focus 去 outline 换 accent 描边 + `--focus-ring`，placeholder `--meta`（§3.11）
- [ ] Toast `role="status" aria-live="polite"`、可撤销按钮 accent 文字（§3.13）

### D. 交互状态与对比度（P0，charter 硬性要求）
- [ ] `:focus-visible` 覆盖全部可交互元素；机制与基准一致（§6：outline 2px accent，offset 2px；`.btn/.cal-cell` 3px）
- [ ] `prefers-reduced-motion` 块存在（§6）
- [ ] hover 只提亮背景/边框，前景色不变淡（`--muted` 禁止）；active 下压 `translateY(1px)`（§5 / §1.5）
- [ ] 视图切换选中态（月/周、主题、分段）可区分（`.on`）

### E. 主 CTA 数量（P0，charter「一动作一主 CTA」）
- [ ] 同一视口内同一动作最多一个实心主按钮；侧边栏 CTA 与页内主 CTA 不重复措辞
- [ ] 重点核对：`灵感雷达`（8 处 btn-primary 候选）、`内容计划`（7 处候选）是否同屏堆叠

### F. 排版（P1）
- [ ] display / body / mono 三套字体栈一致（§1.4）
- [ ] 可比较数字用 mono + tabular-nums（`.num` 或等价类，命名需统一）
- [ ] eyebrow：11px mono、0.14em 字距、大写、accent（§1.4）——`数据复盘` 的 `OPERATIONS REVIEW / 06` 需确认
- [ ] h1/h2 字号走 `--fs-h*` 或 clamp，不另起值（§1.4）

### G. 响应式（P1）
- [ ] ≤920px 侧边栏折叠为顶部横条，导航横向滚动、CTA 收窄、`.side-foot` 隐藏、主题收为色块点（§2.3）
- [ ] 无横向滚动（360–1920 抽查）

### H. 无障碍（P1）
- [ ] 图标按钮 / 日历格子 / 抽屉 / toast 的 aria 属性齐全（§6）
- [ ] 抽屉用 `role="dialog" aria-modal` + 关闭焦点返回（账号矩阵 / 知识资产已见 `inert` 模式，需统一）

### I. 文案与数据（P2）
- [ ] 全 UI 简体中文；品牌名与技术标识原样（§7）
- [ ] 演示数据有标注（「数据为演示占位」等）
- [ ] 不用 emoji 当特征图标

### J. 死代码清理（P2）
- [ ] 无未被 body 引用的遗留壳层/组件 CSS（疑似：`.app{232px}`、`.brand`、`.brand-mark`、`.nav-label`、`.sidebar-foot`、`.topbar`、`.workspace`、`.title-wrap`、`.toolbar`、`.account-tabs`、`.board-shell`、`.board`、`.column`、`.content-card` 等，集中在 4 个 Pattern B 页面）

## 4. 交付物定义

1. **走查报告**（新增 `设计走查-报告.md`）：逐页一行核对 → 偏差表（页面 / 位置 / 规范条款 / 严重度 / 建议修复），附「符合项」清单。
2. **修改清单**：按严重度排序，P0 → P1 → P2；每条给出可执行修法（改哪一行、怎么改），供直接进入修复。

**严重度规则：**
- **P0**：违反已验证规则 / charter 硬性要求（对比度、重叠、超预算主 CTA、焦点环缺失）→ 必须修。
- **P1**：系统性视觉/结构偏离规范条款 → 建议修。
- **P2**：命名、文案、死代码等清洁度问题 → 可选修。
