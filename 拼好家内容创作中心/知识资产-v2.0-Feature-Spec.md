# 知识资产 v2.0 Feature Spec

> 状态：设计完成，待开发  
> 日期：2026-08-06  
> 关联页面：`#/knowledge`  
> 视觉参考：`知识资产-v2.html`  
> 上游模块：数据复盘、内容计划  
> 下游模块：内容计划、今日工作台

---

## 1. 产品定义

知识资产是拼好家运营创作中心的可复用方法库，负责统一维护品牌规范、脚本模板、执行 SOP 和复盘方法。

它不是普通网盘，也不是把复盘文字原样堆积起来的资料库。每一条正式资产都应当能被搜索、阅读、引用和持续修订，并能回答以下问题：

- 这个账号应该用什么语气表达？
- 哪种标题、开场和 CTA 已被验证有效？
- 一类内容应该按什么步骤制作和发布？
- 本周期的数据结论能否转化为下一条内容的具体方法？

核心闭环：

```text
数据复盘
  -> 一键沉淀为待整理草稿
  -> 知识资产整理并发布
  -> 内容计划引用资产
  -> 内容发布与复盘
  -> 继续修订资产
```

### 1.1 一句话设计方向

高密度资产库 + Markdown 文档工作区。列表负责快速扫描和筛选，右侧抽屉负责阅读、编辑、发布和查看来源。

### 1.2 设计读法

这是面向单人或小团队自媒体运营者的高频工作台模块，延续现有 Framer 深色运营界面，强调信息密度、可检索性和跨模块复用，不采用营销页或卡片堆叠式布局。

---

## 2. 问题陈述

当前系统已经能管理内容计划并填写周期复盘结论，但有效经验仍停留在周期表单和个人记忆里：

- 同一种标题或开场被反复从零创作。
- 品牌话术和禁用表达散落在文档中，无法统一查找。
- SOP 更新后缺少明确版本，历史内容无法说明引用的是哪一版。
- 复盘结论包含有效经验、失败原因和下周动作，未经整理直接入库会产生噪声。
- 内容计划尚不能记录引用过哪些知识资产，无法计算方法复用率。

v2.0 要解决的核心问题：

> 把零散经验变成有来源、有状态、有版本、可引用的运营资产。

## 3. 目标与非目标

### 3.1 Goals

| 编号 | 目标 | 验收信号 |
|---|---|---|
| G1 | 用户能创建、阅读、编辑、归档知识资产 | 完成完整 CRUD |
| G2 | 用户能按分类、状态、标签和关键词找到资产 | 筛选和全文搜索可用 |
| G3 | 复盘结论能一键生成待整理资产 | 保存复盘后无需重复粘贴 |
| G4 | 正式资产具有来源和版本 | 详情可查看来源、版本和更新时间 |
| G5 | 内容计划能引用正式资产 | 内容卡可记录资产引用 |
| G6 | 系统能计算方法复用率 | 可统计引用资产的发布内容占比 |

### 3.2 Non-Goals

| 编号 | 本版本不做 | 原因 |
|---|---|---|
| N1 | 不做多人实时协作编辑 | 当前是本地单工作区产品 |
| N2 | 不做附件、图片和视频资产管理 | 本版本聚焦文本方法资产 |
| N3 | 不做复杂文件夹树 | 一级分类 + 标签已足够覆盖当前规模 |
| N4 | 不做 AI 自动改写或自动总结 | 先验证人工沉淀闭环 |
| N5 | 不做完整版本回滚界面 | v2.0 先记录版本和引用快照 |
| N6 | 不做跨工作区共享市场 | 当前仅 `default` 工作区 |

## 4. 方案取舍

### 4.1 备选方案

#### 方案 A：纯卡片资产库

每条资产只包含标题、分类和正文，点击卡片打开编辑表单。

优点：开发快，与静态稿最接近。  
缺点：缺少发布状态、来源、版本和引用关系，无法支撑完整运营闭环。

#### 方案 B：资产库 + Markdown 文档工作区

资产有草稿、正式、归档状态；支持来源追踪、版本递增、标签搜索和内容计划引用。

优点：在现有技术栈内可实现，同时能支撑复盘沉淀和方法复用率。  
缺点：比纯 CRUD 多一组状态和关联表。

#### 方案 C：完整 Wiki

增加文件夹树、双向链接、版本历史、评论和全文关系图。

优点：长期能力最强。  
缺点：远超当前运营规模，开发和维护成本高。

### 4.2 最终选择

采用方案 B。

保留静态稿的四个一级分类，不新增多层目录；使用标签表达“标题、开场、CTA、选题、封面、发布”等细分主题。复盘沉淀先生成草稿，整理并发布后才进入正式资产库。

## 5. 用户与核心场景

### 5.1 主要用户

- 单人自媒体运营者
- 2 至 5 人的小型内容团队
- 同时管理多个账号和三个发布平台的运营者

### 5.2 核心用户故事

| 优先级 | 用户故事 |
|---|---|
| P0 | 我希望新建并编辑一条方法资产，供后续内容复用。 |
| P0 | 我希望通过分类和搜索快速找到需要的品牌话术或脚本模板。 |
| P0 | 我希望把复盘结论一键沉淀为草稿，再整理成正式方法。 |
| P0 | 我希望知道资产来自手动创建还是某次复盘。 |
| P0 | 我希望归档过时资产，而不破坏历史内容中的引用。 |
| P1 | 我希望从知识资产创建内容卡，自动带入模板正文。 |
| P1 | 我希望在内容卡中引用一条或多条资产。 |
| P1 | 我希望看到资产被哪些内容使用过。 |

## 6. 信息架构

### 6.1 一级分类

| 分类代码 | 展示名称 | 内容范围 |
|---|---|---|
| `brand_guide` | 品牌手册 | 定位、语气、称呼、禁用词、视觉与账号规范 |
| `script_template` | 脚本模板 | 标题、开场、结构、转场、CTA、系列模板 |
| `sop` | SOP | 选题、拍摄、剪辑、发布、数据回收、起号流程 |
| `review_method` | 复盘方法 | 数据结论、判断标准、实验方法和可复用规律 |

### 6.2 标签

标签为自由文本，经过 trim、去重和长度限制后保存。推荐标签：

`标题`、`开场`、`CTA`、`选题`、`封面`、`口播`、`发布`、`抖音`、`小红书`、`视频号`、账号名称。

分类负责稳定导航，标签负责灵活检索。不得把标签实现为新的固定分类层级。

### 6.3 状态

| 状态 | 含义 | 列表默认可见 | 可被内容计划引用 |
|---|---|---:|---:|
| `draft` | 待整理或正在编辑 | 是，位于待整理区 | 否 |
| `active` | 已发布的正式资产 | 是，位于资产库 | 是 |
| `archived` | 已过时但保留历史引用 | 否，可筛选查看 | 否 |
| `deleted` | 软删除 | 否 | 否 |

## 7. 页面设计

### 7.1 页面头部

左侧：

- Eyebrow：`METHOD LIBRARY`
- 标题：`知识资产`
- 说明：`把复盘结论和创作经验整理成可搜索、可引用的方法。`

右侧：

- 次按钮：`导出`
- 主按钮：`新建资产`

导出默认导出当前筛选结果为 UTF-8 JSON。没有资产时按钮禁用并提供说明。

### 7.2 概览条

使用无嵌套的横向指标区，不新增装饰卡片。

| 指标 | 定义 |
|---|---|
| 正式资产 | `status = active` 的数量 |
| 待整理 | `status = draft` 的数量 |
| 本月更新 | 本自然月内更新过的资产数量 |
| 本月被引用 | 本自然月产生的引用次数 |

首期没有引用数据时显示 `0`，不使用模拟百分比。

### 7.3 待整理区

仅在存在草稿时显示，位置在概览条和正式资产库之间。

每行字段：

- 标题
- 来源
- 生成时间
- 正文摘要
- `整理并发布`
- `忽略`

复盘生成的草稿默认标题：

```text
{YYYY年第N周复盘} 可复用方法
```

点击“整理并发布”打开资产抽屉，预填分类 `复盘方法`、来源、标签和 Markdown 正文。用户确认后发布为正式资产。

点击“忽略”不物理删除，状态改为 `archived`，避免同一复盘重复生成。

### 7.4 筛选工具栏

桌面端从左到右：

1. 搜索框：搜索标题、摘要、正文和标签
2. 分类分段控件：全部 / 品牌手册 / 脚本模板 / SOP / 复盘方法
3. 状态下拉：正式 / 草稿 / 归档 / 全部
4. 排序：最近更新 / 最近创建 / 使用最多

默认条件：

```text
分类 = 全部
状态 = 正式
排序 = 最近更新
```

筛选条件写入 URL query，刷新后保留：

```text
#/knowledge?q=开场&category=script_template&status=active&sort=updated
```

### 7.5 资产库

桌面端使用响应式网格，卡片只用于一条独立资产，不嵌套其他卡片。

资产卡字段：

- 分类标记
- 来源类型
- 标题
- 最多三行摘要
- 最多三个标签
- 版本号
- 更新时间
- 引用次数

点击整张卡片打开阅读抽屉。卡片内不放编辑、删除等多个微按钮，避免操作拥挤。

排序稳定规则：

```text
主排序字段 DESC, updated_at DESC, id ASC
```

### 7.6 阅读与编辑抽屉

桌面宽度建议 `min(760px, 58vw)`，手机端全屏。

#### 阅读模式

头部：

- 分类、状态
- 标题
- 来源和更新时间
- 关闭按钮

正文：

- 安全渲染 Markdown
- 标签
- 来源详情
- 被引用内容列表

底部操作：

- `从此资产创建内容`
- `编辑`
- 更多菜单：归档、删除

#### 编辑模式

字段：

| 字段 | 控件 | 规则 |
|---|---|---|
| 标题 | 单行输入 | 必填，1 至 80 字 |
| 分类 | Select | 必填，四选一 |
| 标签 | 标签输入 | 最多 12 个，每个最多 20 字 |
| 摘要 | 多行输入 | 可选，最多 160 字；为空时由正文首段生成 |
| 正文 | Markdown textarea | 必填，最多 50,000 字 |
| 状态 | 分段控件 | 草稿 / 正式 |

来源字段只读。手动创建显示“手动创建”，复盘来源显示周期和跳转入口。

保存行为：

- 新建资产：保存为用户选择的草稿或正式状态。
- 编辑正文、标题、分类、摘要或标签：`version + 1`。
- 仅归档或恢复状态：不递增正文版本。
- 保存成功后留在阅读模式并显示 toast。
- 有未保存修改时关闭抽屉，必须确认放弃。

### 7.7 删除与归档

- 常规过时资产优先使用“归档”。
- 删除为软删除，二次确认。
- 已被内容引用的资产仍可归档或软删除，历史引用显示标题和版本快照。
- 删除后不得级联删除内容卡或引用记录。

## 8. 上下游流程

### 8.1 数据复盘沉淀

当前 `review_conclusions` 的五个字段映射为 Markdown：

```markdown
# 有效标题模式
{effective_titles}

# 有效开头模式
{effective_openings}

# 有效 CTA 模式
{effective_ctas}

# 暂停或放弃的选题
{abandon_topics}

# 下周期动作
{next_actions}
```

流程：

1. 用户在数据复盘保存结论，并启用“沉淀为知识资产”。
2. 后端在同一事务中保存复盘结论并创建或更新一条 `draft` 资产。
3. `source_type = review`，`source_review_id` 指向该复盘结论。
4. 知识资产页“待整理”数量增加。
5. 用户整理标题、正文和标签后发布。

幂等规则：

- 同一 `source_review_id` 最多对应一条未删除资产。
- 重复保存复盘时，如果资产仍为草稿，则同步更新草稿正文。
- 如果资产已正式发布，不自动覆盖；页面提示“该复盘已沉淀，可手动修订资产”。

### 8.2 内容计划引用

P1 提供两个入口：

#### 从知识资产创建内容

仅对 `script_template` 和 `sop` 正式资产显示。

1. 点击“从此资产创建内容”。
2. 打开轻量表单，选择账号、内容标题和目标状态。
3. 创建 `content_card`。
4. 脚本模板正文写入 `script_body`；SOP 默认只建立引用，不覆盖脚本。
5. 创建资产引用记录。
6. 跳转 `#/content-plan?card={id}` 并打开内容详情。

#### 在内容卡中引用资产

内容详情增加“引用资产”选择器：

- 只搜索 `active` 资产
- 可多选
- 显示分类、标题和当前版本
- 移除引用只删除关联，不删除资产

### 8.3 引用快照

引用发生时记录：

- 资产 ID
- 资产版本
- 标题快照
- 分类快照

脚本正文若被复制到内容卡，内容卡中的正文之后独立编辑，不随资产更新自动覆盖。

## 9. 数据模型

### 9.1 `knowledge_assets`

```sql
CREATE TABLE IF NOT EXISTS knowledge_assets (
  id TEXT PRIMARY KEY,
  workspace_id TEXT NOT NULL,
  title TEXT NOT NULL,
  category TEXT NOT NULL CHECK (
    category IN ('brand_guide', 'script_template', 'sop', 'review_method')
  ),
  summary TEXT NOT NULL DEFAULT '',
  body TEXT NOT NULL,
  tags_json TEXT NOT NULL DEFAULT '[]',
  source_type TEXT NOT NULL CHECK (
    source_type IN ('manual', 'review', 'content')
  ),
  source_review_id TEXT,
  source_content_card_id TEXT,
  status TEXT NOT NULL CHECK (
    status IN ('draft', 'active', 'archived', 'deleted')
  ),
  version INTEGER NOT NULL DEFAULT 1 CHECK (version >= 1),
  published_at TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  deleted_at TEXT,
  FOREIGN KEY (workspace_id) REFERENCES workspaces(id),
  FOREIGN KEY (source_review_id) REFERENCES review_conclusions(id),
  FOREIGN KEY (source_content_card_id) REFERENCES content_cards(id)
);
```

约束和索引：

```sql
CREATE UNIQUE INDEX IF NOT EXISTS knowledge_assets_review_source
ON knowledge_assets(source_review_id)
WHERE source_review_id IS NOT NULL AND deleted_at IS NULL;

CREATE INDEX IF NOT EXISTS knowledge_assets_workspace_status
ON knowledge_assets(workspace_id, status, updated_at DESC)
WHERE deleted_at IS NULL;

CREATE INDEX IF NOT EXISTS knowledge_assets_workspace_category
ON knowledge_assets(workspace_id, category, updated_at DESC)
WHERE deleted_at IS NULL;
```

`tags_json` 使用 JSON 数组保存。SQLite 查询时使用 `json_each`，不得使用字符串 `LIKE` 判断单个标签。

### 9.2 `knowledge_asset_usages`

```sql
CREATE TABLE IF NOT EXISTS knowledge_asset_usages (
  id TEXT PRIMARY KEY,
  workspace_id TEXT NOT NULL,
  asset_id TEXT NOT NULL,
  content_card_id TEXT NOT NULL,
  usage_type TEXT NOT NULL CHECK (
    usage_type IN ('reference', 'template_copy')
  ),
  asset_version INTEGER NOT NULL,
  title_snapshot TEXT NOT NULL,
  category_snapshot TEXT NOT NULL,
  created_at TEXT NOT NULL,
  FOREIGN KEY (workspace_id) REFERENCES workspaces(id),
  FOREIGN KEY (asset_id) REFERENCES knowledge_assets(id),
  FOREIGN KEY (content_card_id) REFERENCES content_cards(id) ON DELETE CASCADE,
  UNIQUE (asset_id, content_card_id, usage_type)
);
```

索引：

```sql
CREATE INDEX IF NOT EXISTS knowledge_asset_usages_asset
ON knowledge_asset_usages(asset_id, created_at DESC);

CREATE INDEX IF NOT EXISTS knowledge_asset_usages_content
ON knowledge_asset_usages(content_card_id, created_at DESC);
```

## 10. API 契约

所有接口沿用 `{ data, meta }` 成功结构和现有统一错误结构。

### 10.1 列表

```http
GET /api/knowledge-assets
  ?q=
  &category=
  &status=active
  &sort=updated
  &page=1
  &pageSize=24
```

响应：

```json
{
  "data": [],
  "meta": {
    "page": 1,
    "pageSize": 24,
    "total": 0,
    "summary": {
      "active": 0,
      "draft": 0,
      "updatedThisMonth": 0,
      "usageThisMonth": 0
    }
  }
}
```

### 10.2 详情

```http
GET /api/knowledge-assets/:id
```

返回完整正文、来源信息和最近引用内容。

### 10.3 创建

```http
POST /api/knowledge-assets
Content-Type: application/json
```

```json
{
  "title": "开场钩子五秒公式",
  "category": "script_template",
  "summary": "",
  "body": "# 使用步骤\n...",
  "tags": ["开场"],
  "status": "active"
}
```

手动创建时后端固定 `source_type = manual`，不信任客户端传入来源 ID。

### 10.4 更新

```http
PUT /api/knowledge-assets/:id
```

请求必须携带 `version`。服务端只在版本匹配时更新：

```json
{
  "version": 3,
  "title": "开场钩子五秒公式",
  "category": "script_template",
  "summary": "",
  "body": "# 使用步骤\n...",
  "tags": ["开场", "抖音"],
  "status": "active"
}
```

版本冲突返回：

```json
{
  "error": {
    "code": "ASSET_VERSION_CONFLICT",
    "message": "资产已在其他位置更新，请刷新后重试"
  }
}
```

### 10.5 状态操作

```http
POST /api/knowledge-assets/:id/archive
POST /api/knowledge-assets/:id/restore
DELETE /api/knowledge-assets/:id
```

`DELETE` 为软删除。

### 10.6 复盘沉淀

推荐扩展现有复盘保存请求：

```json
{
```

## 11. 校验与安全

### 11.1 服务端校验

- 标题 trim 后 1 至 80 字。
- 正文 trim 后 1 至 50,000 字。
- 摘要最多 160 字。
- 标签最多 12 个，每个最多 20 字，去重后保存。
- 分类和状态只接受枚举值。
- 客户端不得自行指定 `workspace_id`、`source_type` 和来源外键。
- 更新必须校验当前版本，避免静默覆盖。

### 11.2 Markdown 安全

沿用项目当前本地 `marked` 渲染方式，但渲染后必须清理：

- 移除 `script`、`style`、`iframe`、`object`、`embed`。
- 移除所有 `on*` 事件属性。
- 拒绝 `javascript:`、`data:` 和未知协议链接。
- 外链增加 `rel="noopener noreferrer"`。
- 正文不得通过未清理的 `innerHTML` 注入。

## 12. 状态与错误处理

### 12.1 页面状态

| 状态 | 设计 |
|---|---|
| 加载 | 与概览和资产网格形状匹配的骨架，不使用全页转圈 |
| 空库 | “还没有正式资产”，主操作为“新建第一份资产” |
| 无筛选结果 | “没有匹配的资产”，操作为“清除筛选” |
| 仅有草稿 | 正式资产区显示空状态，保留待整理区 |
| 请求错误 | 页面内错误块，提供“重新加载” |
| 保存中 | 保存按钮禁用并显示“保存中...” |
| 保存失败 | 保留表单输入，字段错误就地显示 |
| 版本冲突 | 显示冲突提示，允许刷新最新内容或另存为新资产 |

### 12.2 乐观更新

- 搜索、筛选和抽屉切换只更新前端状态。
- 创建、编辑、归档、删除不做不可逆乐观更新。
- 内容引用可先更新 UI，失败时回滚并 toast。

## 13. 响应式与可访问性

### 13.1 桌面

- 页面沿用现有侧栏和主内容 gutter。
- 概览区四列。
- 资产网格根据可用宽度显示 2 至 3 列。
- 抽屉固定右侧，正文区域可独立滚动。

### 13.2 平板

- 概览区两列。
- 资产网格两列。
- 筛选控件允许换行，不压缩搜索输入到不可用宽度。

### 13.3 手机

- 页面不得横向溢出。
- 概览改为两列紧凑指标。
- 分类分段控件横向滚动。
- 资产网格单列。
- 抽屉全屏，头部和底部操作固定，正文独立滚动。
- 底部主按钮占满可用宽度，删除放入更多菜单。

### 13.4 可访问性

- 所有可交互元素支持键盘和 `focus-visible`。
- 抽屉打开时焦点进入标题或第一个表单字段，关闭后返回触发元素。
- 抽屉使用 `role="dialog"`、`aria-modal="true"` 和明确标题。
- Escape 关闭抽屉；存在未保存修改时先弹确认。
- 动态数量和保存结果使用 `aria-live="polite"`。
- 分类颜色只作辅助，必须同时显示文字。

## 16. 测试计划

### 16.1 后端

- 建表迁移可在已有数据库重复执行。
- 创建手动资产时来源固定为 `manual`。
- 标题、正文、分类、状态和标签校验正确。
- 列表筛选、分页和稳定排序正确。
- 更新正文后版本递增。
- 旧版本更新返回 `ASSET_VERSION_CONFLICT`。
- 归档和软删除不破坏引用。
- 同一复盘重复沉淀保持幂等。
- 复盘保存和知识草稿创建事务一致。
- 工作区数据隔离正确。

### 16.2 前端

- 首屏正确处理加载、成功、空数据和错误。
- 分类、状态、搜索和排序可以组合使用。
- URL query 与界面状态双向同步。
- 阅读模式和编辑模式切换不丢失数据。
- 未保存内容关闭时出现确认。
- 保存失败后表单内容保留。
- Markdown 中危险标签和属性不会执行。
- 抽屉焦点进入、循环和返回正确。
- 手机 360px 宽度无页面横向滚动。

### 16.3 跨模块

- 复盘保存并沉淀后，知识资产待整理数量增加。
- 同一复盘再次保存不会新增重复草稿。
- 正式资产可被内容计划搜索和引用。
- 资产归档后历史内容仍显示引用快照。
- 从模板创建内容卡后脚本正文正确复制。
