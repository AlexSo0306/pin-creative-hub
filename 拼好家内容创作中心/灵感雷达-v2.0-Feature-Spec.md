## 1. Problem Statement

当前灵感雷达 v1 已完成对标作品资料库的基础建设（137 条作品、1 位创作者、2 个平台账号），但存在两个关键断点：

1. **无法发现爆款**：所有作品平铺展示，用户无法快速识别哪些账号近期出了爆款、哪些作品互动异常高，只能逐条人工翻阅。
2. **作品缺少文案正文**：只有标题、标签和互动数，创作者分析竞品时需要打开原始链接对照文案，无法在工作台内完成深度拆解。

**MVP 定位**：监控看板是独立的分析工具。用户在看板中发现爆款 → 阅读文案研究 → **手动去内容计划建选题**。灵感雷达和内容计划在 MVP 阶段不通过代码连接。

**不解决的成本**：用户需要在灵感雷达和浏览器之间反复跳转对照文案，且需要手动记忆或外部记录爆款线索。

## 2. Goals

| # | 目标 | 类型 | 衡量方式 |
|---|------|------|---------|
| G1 | 用户能在 30 秒内识别当前选题空间内互动最高的对标作品 | 用户目标 | 从进入监控看板到定位 Top1 作品的时间 |
| G2 | 用户能在工作台内完成对标作品的文案阅读和拆解，无需跳转外部链接 | 用户目标 | 带文案的作品占比超过 60%（用户主动导入了文案的） |
| G3 | 对标账号和作品数据可通过 CSV 导入维护，普通用户无需脚本或 API | 用户目标 | 新增作品的 80% 通过页面 CSV 导入完成 |
| G4 | 用户能导出筛选后的作品数据用于二次分析 | 用户目标 | 导出功能日活跃度 |

---

## 3. Non-Goals

| # | 不做什么 | 原因 |
|---|---------|------|
| N1 | **不自动爬取平台数据** | 法律与技术风险（反爬、IP封禁、验证码），MVP 只做手动导入 |
| N2 | **不实现灵感转选题（灵感雷达 → 内容计划的数据连接）** | MVP 阶段监控看板是独立的分析工具，用户手动去内容计划建选题 |
| N3 | **不实现浏览器插件一键导入** | 开发成本高，P1 考虑，MVP 用 CSV + MD 批量导入覆盖 |
| N4 | **不实现异常波动自动提醒** | MVP 不做推送/弹窗/邮件等主动提醒，爆款通过看板排行榜人工发现 |
| N5 | **不改变选题空间的数据隔离逻辑** | 保持现有架构，一个空间对应一组独立的创作者、账号和作品数据 |
| N6 | **不引入多用户/权限/云端同步** | 仍是本地单机工作台 |

## 4. User Stories

### 4.1 对标账号管理

| 优先级 | 用户故事 |
|--------|---------|
| P0 | 作为自媒体运营，我希望创建一个参考创作者档案（名称 + 抖音链接 + 小红书链接），以便在一个地方管理该创作者的所有平台账号。 |
| P0 | 作为自媒体运营，我希望查看某个创作者在各平台绑定了哪些账号，以便确认监控覆盖是否完整。 |
| P1 | 作为自媒体运营，我希望编辑或删除已有的参考创作者和平台账号，以便在创作者停更或方向改变时调整监控范围。 |
| P2 | 作为自媒体运营，我希望导入一份创作者名单（CSV），批量创建多个参考创作者档案。 |

### 4.2 作品数据导入

| 优先级 | 用户故事 |
|--------|---------|
| P0 | 作为自媒体运营，我希望上传一份 CSV 文件（含作品标题、平台、作者、发布时间、点赞数、收藏数、播放量、链接等），系统自动解析并导入到当前选题空间，以便批量更新对标作品库。 |
| P0 | 作为自媒体运营，我希望导入时系统对重复作品（同平台 + 同作品 ID）自动跳过并提示，以免数据冗余。 |
| P0 | 作为自媒体运营，我希望导入完成后看到成功/失败/跳过的数量汇总，以便确认导入结果。 |
| P1 | 作为自媒体运营，我希望在导入前预览 CSV 前 5 行数据并手动映射字段名（当 CSV 列名与系统字段不一致时），以免格式问题导致导入失败。 |
| P2 | 作为自媒体运营，我希望导入失败时有逐行的错误原因说明，以便针对性修复 CSV。 |

### 4.3 文案管理

| 优先级 | 用户故事 |
|--------|---------|
| P0 | 作为自媒体运营，我希望上传一个 ZIP 压缩包（内含多个 .md 文件，文件名包含作品标题），系统自动将每个 .md 文件的内容绑定到匹配的作品上，以便在工作台内直接查看对标作品的文案。 |
| P0 | 作为自媒体运营，我希望在作品详情中查看已绑定的文案内容（Markdown 渲染），以便在不跳转平台的情况下分析竞品的标题结构、正文写法、CTA 设计。 |
| P0 | 作为自媒体运营，我希望看到哪些作品已绑定文案、哪些还没有，以便知道哪些还需要补充。 |
| P1 | 作为自媒体运营，我希望手动上传单个 .md 文件并手动选择绑定到某条作品（当自动匹配失败时），以便处理标题不一致的情况。 |
| P2 | 作为自媒体运营，我希望在工作台内直接编辑已绑定的文案内容（如添加标注、高亮关键句）。 |

### 4.4 监控看板

| 优先级 | 用户故事 |
|--------|---------|
| P0 | 作为自媒体运营，我希望在看板中看到单个对标账号近期的播放量/点赞数趋势图（折线图），以便判断该账号是上升期还是衰退期。 |
| P0 | 作为自媒体运营，我希望在看板中看到单条作品与该作者近 10 条均值的对比（如"点赞数超均值 200%"，高亮标记），以便快速发现爆款。 |
| P0 | 作为自媒体运营，我希望在看板中看到"表现最佳"的作品排行榜（Top 5 点赞 / Top 5 播放），以便优先研究最有价值的竞品内容。 |
| P0 | 作为自媒体运营，我希望在看板中看到当前选题空间的总体数据摘要（账号数、作品总数、近期新增数），以便快速了解监控规模。 |
| P1 | 作为自媒体运营，我希望能自定义爆款判定阈值（如"点赞数超均值 X 倍"），以便适配不同量级的账号。 |
| P1 | 作为自媒体运营，我希望按日/周/月切换看板的聚合粒度，以便在不同时间尺度上分析趋势。 |
| P2 | 作为自媒体运营，我希望看板支持跨账号对比（如两个创作者在同一时间段的播放量对比），以便横向评估竞品。 |

### 4.5 数据导出

| 优先级 | 用户故事 |
|--------|---------|
| P0 | 作为自媒体运营，我希望将当前筛选后的作品列表导出为 CSV 文件，以便在 Excel 中做进一步的排序、透视和分析。 |
| P1 | 作为自媒体运营，我希望导出时自选字段（如只导出标题、平台、点赞数、链接），以免导出不需要的数据。 |

## 5. Requirements

### 5.1 对标账号管理增强（Must-Have P0）

#### 5.1.1 创建参考创作者

**触发入口**：灵感雷达 → 对标账号 Tab → "添加创作者"按钮

**表单字段**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 创作者名称 | 文本 | 是 | 如"居里富人" |
| 抖音主页链接 | URL | 否 | 如 `https://www.douyin.com/user/xxx` |
| 小红书主页链接 | URL | 否 | 如 `https://www.xiaohongshu.com/user/profile/xxx` |

**验收标准**：
- [ ] Given 用户进入对标账号 Tab，When 点击"添加创作者"，Then 弹出表单，包含上述三个字段。
- [ ] Given 用户填写创作者名称并保存，When 名称与现有创作者重复，Then 提示"该创作者已存在"，不创建。
- [ ] Given 用户填写抖音或小红书链接，When 保存，Then 系统自动解析链接中的平台标识和账号 ID，创建对应的平台账号记录并关联到该创作者。
- [ ] Given 用户仅填写创作者名称、不填任何链接，When 保存，Then 创建成功，后续可手动补加平台账号。

**数据模型变更**：现有 `Creator` 对象已支持多平台账号，本次增强前端表单即可，数据结构无需变更。

#### 5.1.2 查看创作者详情

**触发入口**：对标账号 Tab → 点击创作者名称

**展示内容**：
- 创作者名称
- 绑定的平台账号列表（平台图标 + 账号 ID + 主页链接 + 收录作品数 + 收录进度标签）
- 该创作者的作品数量汇总

**验收标准**：
- [ ] Given 创作者绑定了抖音和小红书两个账号，When 查看详情，Then 两个账号并列展示，各自的收录进度独立显示。
- [ ] Given 创作者只有名称、未绑定任何平台账号，When 查看详情，Then 显示"暂未绑定平台账号"提示。

### 5.2 CSV 批量导入作品（Must-Have P0）

#### 5.2.1 上传与解析

**触发入口**：灵感雷达 → 作品列表顶部 → "导入作品"按钮

**支持的 CSV 格式**（标准模板）：

| 列名 | 必填 | 类型 | 示例 |
|------|------|------|------|
| `platform` | 是 | 枚举 | `douyin` 或 `xiaohongshu` |
| `post_id` | 是 | 字符串 | 平台作品唯一 ID |
| `title` | 是 | 字符串 | "改造3㎡玄关，收纳翻倍" |
| `author` | 是 | 字符串 | 创作者名称（需与系统中已创建的匹配） |
| `publish_time` | 是 | ISO 8601 | `2026-07-15` 或 `2026-07-15T14:30:00` |
| `likes` | 否 | 整数 | `3240` |
| `bookmarks` | 否 | 整数 | `892` |
| `plays` | 否 | 整数 | `52000` |
| `comments` | 否 | 整数 | `156` |
| `shares` | 否 | 整数 | `43` |
| `url` | 否 | URL | 作品原始链接 |
| `tags` | 否 | 逗号分隔 | `"玄关收纳,小户型,改造"` |

**验收标准**：
- [ ] Given 用户上传符合模板的 CSV，When 系统解析，Then 识别所有列，按 `platform + post_id` 去重。
- [ ] Given CSV 中 `author` 匹配到系统中已存在的创作者，When 导入，Then 作品自动关联到该创作者。
- [ ] Given CSV 中 `author` 在系统中不存在，When 导入，Then **整行跳过并在结果中提示"作者不存在"**，不自动创建创作者。
- [ ] Given CSV 缺少 `platform` 或 `post_id` 列，When 上传，Then 提示"CSV 格式不符合模板，缺少必填列：xxx"，不进入解析。
- [ ] Given CSV 中某行的 `publish_time` 格式无法解析，When 导入，Then 该行跳过并提示"日期格式错误"。

#### 5.2.2 导入结果反馈

**导入完成后显示**：

```
导入完成
- 成功导入：45 条
- 跳过（重复）：12 条
- 失败：3 条
  - 第 8 行：作者"xxx"不存在
  - 第 23 行：日期格式错误
  - 第 41 行：platform 字段值无效
```

**验收标准**：
- [ ] Given 导入全部成功，When 完成，Then 显示成功数量和简洁的"查看作品列表"按钮。
- [ ] Given 有跳过或失败，When 完成，Then 展开失败明细，每条标注行号和原因。
- [ ] Given 用户关闭导入结果弹窗，When 回到作品列表，Then 列表自动刷新，新作品可见。

#### 5.2.3 去重逻辑

- 去重键：**`platform` + `post_id`**（大小写不敏感，前后去空格）
- 重复时：保留已有记录，跳过 CSV 中的该行，**不更新已有数据**
- 边界：`post_id` 为空时，该行直接失败

### 5.3 文案 MD 批量导入与匹配（Must-Have P0）

#### 5.3.1 上传方式

**触发入口**：灵感雷达 → "导入文案"按钮（独立于 CSV 导入）

**支持格式**：一个 ZIP 压缩包，内含多个 `.md` 文件

**文件命名约定**：`《作品标题》.md` 或 `作品标题.md`（如 `《改造3㎡玄关，收纳翻倍》.md`）

**验收标准**：
- [ ] Given 用户上传一个含 20 个 .md 文件的 ZIP，When 系统解压，Then 识别所有 .md 文件，忽略其他格式。
- [ ] Given ZIP 内不含任何 .md 文件，When 上传，Then 提示"未找到 .md 文件"。

#### 5.3.2 匹配逻辑

**匹配规则**：

1. 提取文件名中的作品标题部分（去掉书名号 `《》` ）
2. 在当前选题空间中**模糊匹配**作品标题
3. 匹配算法：文本相似度 ≥ 80% 视为候选匹配
4. 每个 .md 文件匹配结果分类：

| 结果 | 定义 | 处理方式 |
|------|------|---------|
| 精确匹配 | 有且仅有一条作品标题完全一致 | **自动绑定** |
| 模糊匹配 | 有 1-N 条候选作品 | **展示候选列表，用户手动确认** |
| 无匹配 | 没有相似度 ≥ 80% 的作品 | 跳过，提示"未找到匹配作品" |

**验收标准**：
- [ ] Given `.md` 文件名与作品标题完全一致（忽略全半角标点、首尾空格），When 导入，Then 自动绑定，无需用户确认。
- [ ] Given `.md` 文件名与 3 条作品标题相似度均超过 80%，When 导入，Then 展示候选列表，每行显示"文件名 → 作品标题 + 平台 + 作者"，用户勾选确认后再绑定。
- [ ] Given `.md` 文件名与任何作品标题相似度低于 80%，When 导入，Then 该文件跳过，汇总结果中标注"未匹配"。
- [ ] Given 一条作品已有文案，When 再次导入匹配到该作品的 .md 文件，Then 提示"该作品已有文案，是否覆盖？"
- [ ] Given 用户取消模糊匹配的确认，When 取消，Then 该文件的文案不绑定到任何作品。

#### 5.3.3 文案查看

**展示位置**：作品详情面板（点击作品列表中的某条作品 → 展开详情）

**新增展示区**（现有作品详情只有标题、标签、指标、链接）：

```
┌─────────────────────────────────┐
│ 文案内容 (Markdown)              │
│ ─────────────────────────────── │
│                                 │
│ 《改造3㎡玄关，收纳翻倍》          │
│                                 │
│ ## 痛点切入                      │
│ > 你家玄关是不是也这样：          │
│ > 鞋子堆一地，包包没处放...       │
│                                 │
│ ## 改造方案                      │
│ 1. 利用门后空间...               │
│                                 │
│ [查看原文 →]                     │
│                                 │
│ 文案状态：已匹配 | 2026-07-15   │
└─────────────────────────────────┘
```

**验收标准**：
- [ ] Given 作品已绑定文案，When 用户展开作品详情，Then 渲染 Markdown 内容（支持标题、列表、引用、加粗等基本语法）。
- [ ] Given 作品未绑定文案，When 用户展开作品详情，Then 显示"暂未导入文案，点击此处上传"。
- [ ] Given 文案内容超过 500 字，When 展示，Then 默认折叠，显示"展开全文"按钮。
- [ ] Given 用户点击"查看原文"，When 跳转，Then 新窗口打开作品的原始链接。

#### 5.3.4 文案状态标记

在作品列表中，每条作品右侧新增一个文案状态图标：

| 状态 | 图标/标签 | 含义 |
|------|----------|------|
| 已绑定 | ✓ 文案 | 已成功匹配并绑定 |
| 未绑定 | — | 未上传或匹配失败 |

### 5.4 监控看板（Must-Have P0）

#### 5.4.1 看板入口与布局

**触发入口**：灵感雷达内的新 Tab ——"监控看板"（与"历史作品""对标账号"并列）

**看板页面布局**（自上而下）：

```
┌──────────────────────────────────────┐
│ 数据摘要行                            │
│ 账号 5 | 作品 238 | 近7日新增 18      │
├──────────────────────────────────────┤
│                                      │
│ 趋势图（折线图，占页面宽度 50%）        │
│ 所选账号近期发布量/互动量趋势           │
│                                      │
├──────────────┬───────────────────────┤
│ 爆款排行      │ 数据明细表             │
│ Top 5 点赞    │ 按指标排序的作品列表    │
│ Top 5 播放    │                       │
│              │                       │
└──────────────┴───────────────────────┘
```

#### 5.4.2 账号趋势图（折线图）

**X 轴**：时间（按日聚合，默认最近 30 天）  
**Y 轴**：指标值（点赞数 / 播放量，可切换）  
**数据源**：当前选定作者在指定时间范围内所有作品的 `publish_time` + 对应指标

**验收标准**：
- [ ] Given 用户选择作者"居里富人"和指标"点赞数"，When 查看趋势图，Then 展示该作者近 30 天每日发布的点赞数折线（如当天无发布，则跳过该日期）。
- [ ] Given 用户切换指标为"播放量"，When 切换，Then 折线图数据对应切换。
- [ ] Given 作者选择为"全部"，When 查看趋势图，Then 聚合当前空间所有作者的数据。
- [ ] Given 时间范围内该作者无作品数据，When 查看，Then 显示"暂无数据"。
- [ ] Given 用户鼠标悬停于某个数据点，When 悬停，Then 显示 tooltip：日期 + 具体数值。

**技术备注**：使用 Chart.js（CDN 引入），折线图组件。

#### 5.4.3 爆款检测与排行

**爆款上榜条件**：单条作品点赞数 > 该作者近 10 条作品点赞均值的指定倍数（默认 2 倍）

**排行榜展示**：

```
┌─ 爆款排行 ──────────────────────────┐
│                                     │
│ 🔥 点赞数超均值 320%                  │
│ 《改造3㎡玄关》                       │
│ 居里富人 · 抖音 · 点赞 3,240          │
│                                     │
```

**验收标准**：
- [ ] Given 作者近 10 条点赞均值为 1000，某条点赞 3200，When 看板加载，Then 该条以"🔥 超均值 220%"展示。
- [ ] Given 该作者作品不足 2 条，When 加载，Then 无法计算均值，不展示爆款排行，显示"数据不足，至少需要 2 条作品"。
- [ ] Given 用户修改爆款阈值（如改为 1.5 倍），When 修改并保存，Then 排行按新阈值重新计算。

**阈值配置**（看板设置入口）：

| 规则 | 默认值 | 说明 |

### 5.5 数据导出（Must-Have P0）

**触发入口**：灵感雷达 → 作品列表顶部 → "导出"按钮

**导出内容**：当前筛选条件下的所有作品（受平台筛选、创作者筛选、关键词搜索影响）

**导出字段**（固定，P0 不开放自选）：

| 列名 | 对应数据字段 |
|------|------------|
| 平台 | platform |
| 作者 | author |
| 标题 | title |
| 发布时间 | publish_time |
| 点赞数 | likes |
| 收藏数 | bookmarks |
| 播放量 | plays |
| 评论数 | comments |
| 标签 | tags（逗号分隔） |
| 原始链接 | url |
| 是否有文案 | content_bound (是/否) |

**验收标准**：
- [ ] Given 用户筛选了"抖音 + 居里富人"，When 点击导出，Then 生成的 CSV 仅含满足该筛选条件的作品。
- [ ] Given 当前筛选结果为空（0 条），When 点击导出，Then 按钮置灰，tooltip 提示"没有可导出的数据"。
- [ ] Given 筛选结果超过 500 条，When 导出，Then 正常生成文件（不截断）。
- [ ] Given CSV 导出成功，When 保存，Then 文件名格式为 `灵感雷达_家居_2026-08-03.csv`。

## 8. 用户路径

### 8.1 核心路径：发现爆款 → 研究文案 → 手动建选题

```
1. 用户进入灵感雷达 → 监控看板
2. 看板突出显示 🔥 爆款排行，用户一眼看到"点赞超均值 320%"的作品
3. 点击作品 → 展开详情 → 查看已绑定的 Markdown 文案
4. 在详情中阅读分析竞品的痛点切入、结构、CTA
5. 用户切换到内容计划模块 → 手动新建选题（复制对标信息）
```

### 8.2 数据维护路径：批量更新作品库

```
1. 用户从浏览器插件或其他工具导出对标作品 CSV
2. 进入灵感雷达 → 点击"导入作品" → 上传 CSV
3. 系统自动解析 → 去重 → 导入 → 显示结果汇总
4. 用户将竞品文案另存为 .md 文件 → 打包为 ZIP
5. 点击"导入文案" → 上传 ZIP → 模糊匹配 → 手动确认 → 绑定
6. 回到作品列表，带文案标记的作品可直接深度研究
```
